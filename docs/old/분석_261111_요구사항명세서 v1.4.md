## 1. 개요

본 문서는 스마트보카의 상세한 기능 요구사항과 비기능 요구사항을 명시합니다.

### 1.1 용어 정의

| 용어 | 설명 |
|------|------|
| **학생** | 스마트보카 앱을 사용하는 사용자 |
| **단어** | 학습 대상이 되는 영문 단어 |
| **분야** | 단어의 학습 구분. v1.1에서는 `일상`, `비즈니스`, `미분류` 3개로 고정 (사용자 정의 분야 신설은 v1.2 이후 검토) |
| **난이도** | 단어 난이도 1~5 (`Word.level`, CSV의 `level` 열과 같은 값). 입력하지 않으면 1 |
| **진도(Progress)** | 학생이 각 단어에 대해 이룬 학습 성과 |
| **시도 횟수** | 단어의 정답 횟수 + 오답 횟수 (`correct_count + wrong_count`) |
| **정답률** | 정답 횟수 ÷ 시도 횟수 × 100. 시도 횟수가 0이면 정답률은 없음(`NULL`)으로 보고 표시는 `-` |
| **연속 정답** | 마지막 시도부터 거꾸로 세었을 때 연속으로 맞춘 횟수 (`consecutive_correct`). 오답 시 0 |
| **상태** | 단어의 학습 단계. `미학습`, `학습중`, `복습필요`, `숙달` (2.4 참조) |
| **숙달** | 연속 정답 5회 이상인 상태 |
| **학습 완료 단어** | 상태가 `숙달`인 단어 |
| **오늘** | 시스템 로컬 시간 기준 날짜. 자정(00:00)에 전환 (6장 참조) |
| **복습 예정일** | 간격 반복 알고리즘에 의해 정해진 다음 복습 날짜 (`next_review_date`) |
| **복습 대상** | 복습 예정일이 오늘 이하인 단어 |
| **신규·약한 단어** | 시도 횟수가 0이거나 정답률이 70% 미만인 단어 |
| **자주 틀린 단어** | 정답률이 60% 미만이고, 마지막 복습일이 7일 이상 지난 단어 |
| **퀴즈** | 학생이 풀어야 할 문제 (4지선다형) |
| **기본 퀴즈** | 오늘 구성된 퀴즈 전체 (N문항) |
| **보너스 문제** | 기본 퀴즈 완료 후 자동 추천되는 추가 문제 |

## 2. 기능 요구사항 (FRD: Functional Requirements)

### 2.1 단어 관리 기능

#### FR-1.1: 초기 데이터 로드
**목적**: 앱 첫 실행 시 1,500개 단어를 DB에 자동 로드

**상세 요구사항**:
- [ ] 앱 첫 실행 시 DB 존재 여부 확인
- [ ] DB 없으면 init_db.py 자동 실행
- [ ] `data/words_common.csv` (일상 1,000개) 로드, 분야는 `일상`
- [ ] `data/words_business.csv` (비즈니스 500개) 로드, 분야는 `비즈니스`
- [ ] 각 단어의 Progress 초기화 (상태: 미학습, correct_count: 0, wrong_count: 0, consecutive_correct: 0)
- [ ] 로드 완료 메시지 표시 또는 자동으로 진행

**성공 기준**:
- DB 파일 생성됨
- Word 테이블에 1,500개 레코드
- Progress 테이블에 1,500개 레코드 (모두 미학습)

---

#### FR-1.2: 단어 조회
**목적**: 학생이 등록된 단어 목록을 확인

**화면**: 단어 관리 탭

**상세 요구사항**:
- [ ] 테이블 형식으로 단어 목록 표시
  - 열: 단어(영어) | 뜻(한글) | 상태 | 습득도(%) | 마지막복습 | 정답횟수
- [ ] 페이지네이션 (1페이지당 20개 표시)
- [ ] 분야별 필터링 (`일상` / `비즈니스` / `미분류` / 전체)
- [ ] 키워드 검색 (단어 또는 뜻)
- [ ] 정렬 기능 (단어순, 상태순, 진도순)
- [ ] 습득도가 없는 단어(시도 0)는 `-`로 표시하고, 정렬 시 맨 뒤에 둔다

**성공 기준**:
- 20개씩 정상 표시
- 검색 결과 정확함
- 필터링 작동

---

#### FR-1.3: 단어 추가
**목적**: 학생이 새로운 단어를 등록

**화면**: 단어 관리 탭 - 추가 버튼

**상세 요구사항**:
- [ ] 팝업 또는 새 화면으로 입력 폼 표시
  - 입력 필드: 영어(필수), 한글(필수), 분야(선택, 기본값 `미분류`), 난이도(1-5, 선택)
- [ ] 영어 중복 검사 (같은 단어 이미 존재 시 경고, 검사 기준은 FR-1.7-A 참조)
- [ ] 저장 시 Word 테이블에 추가
- [ ] 자동으로 Progress 생성 (미학습 상태)
- [ ] 성공 메시지 표시

**성공 기준**:
- 단어 저장 완료
- Progress 자동 생성
- 목록에 즉시 반영

---

#### FR-1.4: 단어 삭제
**목적**: 학생이 불필요한 단어 제거

**화면**: 단어 관리 탭

**상세 요구사항**:
- [ ] 단어 옆에 삭제 버튼
- [ ] 클릭 시 확인 대화상자 ("정말 삭제하시겠어요?")
- [ ] 확인 시 Word 레코드 삭제
- [ ] 관련 Example, Progress, Quiz 레코드도 삭제 (CASCADE)
  - 삭제된 단어의 퀴즈 기록은 통계에서도 제외된다. 삭제 확인 대화상자에 "학습 기록도 함께 삭제됩니다"를 표시한다.
- [ ] 성공 메시지 표시

**성공 기준**:
- DB에서 단어 제거됨
- 관련 데이터도 함께 제거됨
- UI에서 즉시 반영

---

#### FR-1.5: 예문 표시
**목적**: 단어별 예문을 보여준다. 예문은 CSV 기본 예문과 학생 직접 입력으로만 얻는다. 외부 사전 API는 사용하지 않는다.

**트리거**: 단어 상세 보기 열기

**상세 요구사항**:
- [ ] CSV 기본 예문(`example_1`~`example_3`)은 초기 DB 생성 시 Example 테이블에 `source: "builtin"`으로 저장한다 (FR-1.1)
- [ ] 단어 상세 보기에 저장된 예문을 모두 표시한다
- [ ] 학생이 추가한 신규 단어는 예문이 없으므로, 예문을 직접 입력하도록 안내한다 (FR-1.6)
- [ ] 예문이 3개 미만이면 "예문이 부족합니다. 직접 추가해 보세요" 안내를 표시한다
- [ ] "예문 조회"·"예문 재조회" 버튼은 없다. 인터넷 연결을 사용하지 않는다

**성공 기준**:
- CSV 기본 예문 3개가 상세 보기에 표시됨
- 인터넷 연결 없이 예문 표시가 동작함

---

#### FR-1.6: 사용자 예문 추가
**목적**: 학생이 직접 예문을 입력해서 추가

**화면**: 단어 상세 보기

**상세 요구사항**:
- [ ] 예문 입력 필드 (빈 값·공백만 입력은 저장하지 않음)
- [ ] 추가 버튼
- [ ] 입력된 예문을 Example 테이블에 저장 (source: "user")
- [ ] 단어당 사용자 예문 개수 상한은 두지 않는다
- [ ] 목록에 즉시 추가됨

**성공 기준**:
- 사용자 예문 저장 완료
- 목록에 표시됨

---

#### FR-1.7: 단어 수정 (v1.1 추가)
**목적**: 등록된 단어의 영어·뜻·분야·난이도를 수정

**화면**: 단어 관리 탭 - 단어 상세 보기 - 수정 버튼

**상세 요구사항**:
- [ ] 수정 가능 항목: 영어, 한글, 분야, 난이도
- [ ] **FR-1.7-A 중복 검사 기준**: 영어를 비교할 때 앞뒤 공백을 제거하고 대소문자를 무시한다 (`Apple` = `apple` = ` apple `). 뜻(한글)은 중복 판정에 쓰지 않는다. 수정 시에도 같은 기준을 적용하며, 자기 자신은 제외한다.
- [ ] 영어를 수정해도 Progress(학습 기록)와 Example은 유지된다.
- [ ] 저장 시 성공 메시지 표시, 목록에 즉시 반영
- [ ] 수정 취소 시 변경 없이 이전 화면으로 복귀

**성공 기준**:
- 수정 내용이 DB와 목록에 반영됨
- 중복 영어로 수정하면 경고가 표시되고 저장되지 않음

---

#### FR-1.8: 백업 및 복구 (v1.1 추가)
**목적**: 학습 기록을 파일로 보관하고, 필요할 때 복원

**화면**: 설정 탭 - 데이터 관리 영역

**상세 요구사항**:
- [ ] 수동 백업: "백업 만들기" 버튼 → 사용자가 저장 위치를 선택 → DB 파일을 복사해 저장
- [ ] 복구: "백업에서 복구" 버튼 → 백업 파일 선택 → 확인 대화상자 ("현재 학습 기록이 백업 파일로 바뀝니다") → 확인 시 현재 DB를 자동 백업한 뒤 복원
- [ ] 자동 백업: 앱 종료 시 `backups/` 폴더에 날짜별 백업을 만들고, 최근 3개만 유지한다
- [ ] 백업 파일이 손상되었거나 SmartVoca DB가 아니면 복구를 거부하고 안내한다
- [ ] 백업·복구 완료 메시지 표시

**성공 기준**:
- 백업 파일로 복구했을 때 단어·진도·퀴즈 기록이 백업 시점과 같음
- 복구 전 현재 DB가 자동 백업됨

### 2.2 학습 설정 기능

#### FR-2.1: 학습 분야 선택
**목적**: 학생이 학습할 분야를 선택

**화면**: 설정 탭

**상세 요구사항**:
- [ ] 선택 옵션: 일상 / 비즈니스 / 선택안함(전체)
- [ ] 선택 시 Settings 테이블에 저장

**성공 기준**:
- 선택한 분야가 저장됨
- 다음 퀴즈 세션부터 반영됨

**목적**: 학생이 하루에 학습할 단어 개수를 결정

- 선택값 저장됨

### 2.3 퀴즈 기능

#### FR-3.1: 오늘의 퀴즈 구성
**목적**: 간격 반복 알고리즘에 따라 오늘 풀 퀴즈를 자동 생성

**트리거**: 학생이 "퀴즈 시작" 버튼 클릭

**상세 요구사항**:
- [ ] 설정된 일일 학습량(N개) 확인
- [ ] 분야 설정이 `전체`가 아니면 해당 분야의 단어만 대상으로 한다.
- [ ] **단어 선정 비율** (FR-3.1-A):
  - 신규·약한 단어: 50~70% (기본 70%)
  - 복습 대상(복습 예정일이 오늘 이하): 20~30% (기본 20%)
  - 자주 틀린 단어: 10~20% (기본 10%)
- [ ] **개수 계산** (FR-3.1-B): 같은 날 여러 번 계산해도 같은 결과가 나오도록 아래 순서로 정한다.
  1. 자주 틀린 단어 수 = `floor(N × 0.10)`
  2. 복습 대상 수 = `floor(N × 0.20)`
  3. 신규·약한 단어 수 = `N − (1 + 2)`
  - 예: N=10 → 신규·약한 7, 복습 2, 자주 틀린 1
- [ ] **선정 순서** (FR-3.1-C): 자주 틀린 단어 → 복습 대상 → 신규·약한 단어 순으로 뽑는다. 이미 뽑은 단어는 다음 버킷에서 제외한다.
- [ ] **단어 부족 시 처리** (FR-3.1-D):
  - 해당 버킷의 단어가 모자라면 남는 개수를 신규·약한 단어에서 채운다.
  - 그래도 부족하면 아직 뽑히지 않은 나머지 단어(숙달 상태 포함)에서 채운다.
  - 등록된 단어(분야 필터 적용 후)가 N보다 적으면 퀴즈 문항 수는 그 개수로 줄이고, "오늘 퀴즈는 N개 중 M개입니다" 안내를 표시한다.
- [ ] **4지선다형 보기 생성** (FR-3.1-E): 보기 3개(오답)를 아래 순서로 채운다.
  1. 같은 분야 + 난이도 ±1 + 정답 뜻과 다른 단어
  2. 같은 분야 (난이도 조건 해제)
  3. 전체 단어 중 무작위
  - 정답과 같은 한글 뜻을 가진 단어는 보기에서 제외한다.
  - 난이도는 모든 단어에 값이 있으므로(미입력 시 1) 난이도 조건을 항상 적용한다.
  - 보기 후보가 3개 미만이면 해당 문항은 "보기를 만들 수 없음"으로 건너뛰고, 오늘 퀴즈에서 제외한다.
- [ ] **동의어 중복 방지** (FR-3.1-F): 한글 뜻이 같은 단어는 한 퀴즈에 한 번만 뽑는다. 선정 순서(자주 틀린 → 복습 대상 → 신규·약한 → 부족분 보충)대로 뽑되, 이미 뽑힌 단어와 뜻이 같은 단어는 건너뛴다 (설계서 ADR-08).
- [ ] 선정된 단어들로 퀴즈 목록 생성 (문항 순서는 무작위)

**성공 기준**:
- N개의 문제가 생성됨 (단어 부족 안내가 있는 경우 제외)
- 비율이 대략 맞음 (오차 범위 ±5%)
- 4지선다형 보기가 정확함 (정답 1개 + 서로 다른 뜻의 오답 3개)

---

#### FR-3.2: 4지선다형 양방향 퀴즈 출제
**목적**: 퀴즈를 한→영, 영→한 두 방향으로 출제

**퀴즈 화면**

**상세 요구사항**:
- [ ] 문제 유형 비율: 한글→영어와 영어→한글을 `floor(N/2)`, `N − floor(N/2)`로 나눈다. (N이 홀수면 영어→한글이 1개 많다.)
- [ ] 한글→영어: "사과는?" → 4개 선택지
- [ ] 영어→한글: "apple은?" → 4개 선택지
- [ ] 각 문제마다:
  - 문제 텍스트 표시
  - 4개 선택지 버튼 (선택 전에는 활성화 상태 유지)
  - 정답 선택하면 즉시 채점
  - 결과 표시 (✓ 정답 / ✗ 오답)
  - 오답이면 정답 선택지를 강조 표시 (v1.1 추가)
  - [다음 문제] 또는 [완료] 버튼

**성공 기준**:
- 한→영, 영→한 모두 출제됨
- 비율 정확함
- 채점 정상 작동
- 오답 시 정답이 표시됨

---

#### FR-3.3: 퀴즈 채점 및 기록
**목적**: 학생의 정답/오답을 기록하고 진도 업데이트

**트리거**: 학생이 정답 선택

**상세 요구사항**:
- [ ] Quiz 테이블에 기록:
  - word_id, quiz_type(한→영/영→한), is_correct(true/false), is_bonus(true/false), is_retry(true/false), created_date
- [ ] **진도 반영 규칙** (FR-3.3-A):
  - 같은 날 첫 번째 세션에서 푼 문항만 Progress에 반영한다.
  - 같은 날 "다시 풀기"로 푼 문항(`is_retry = true`)은 Quiz 기록만 남기고 Progress는 바꾸지 않는다.
  - 재풀이 세션 판정: 세션 시작 시 오늘 Quiz 기록 중 `is_bonus = 0 AND is_retry = 0` 행이 있으면 재풀이 세션으로 본다.
- [ ] Progress 테이블 업데이트 (반영 대상 문항):
  - 정답: correct_count +1, consecutive_correct +1, last_reviewed_date = 오늘
  - 오답: wrong_count +1, consecutive_correct = 0, last_reviewed_date = 오늘
  - correct_rate = correct_count / (correct_count + wrong_count) × 100 (시도 0이면 NULL)
  - 상태 업데이트 (2.4 규칙)
  - next_review_date 계산 (2.4 간격 규칙)
- [ ] 화면에 결과 표시

**성공 기준**:
- 데이터 정확하게 저장됨
- 진도율 정확하게 계산됨
- 같은 날 다시 풀기 후에도 진도 수치가 바뀌지 않음

---

#### FR-3.4: 보너스 문제 제시
**목적**: 기본 퀴즈 완료 후 약한 단어 집중 공략

**트리거**: 기본 퀴즈 N문항 전체 완료

**상세 요구사항**:
- [ ] 보너스 대상 선정:
  - 조건: 자주 틀린 단어 (정답률 < 60% AND 마지막 복습일이 7일 이상 전)
  - 단, 오늘 기본 퀴즈에 이미 나온 단어는 제외한다.
  - 뜻 중복 제외: 기본 퀴즈에 나온 단어와 한글 뜻이 같은 단어도 제외한다 (FR-3.1-F).
  - 우선순위: 정답률 낮은 순 → 마지막 복습일이 오래된 순
- [ ] 보너스 개수: 최대 5개. 조건을 만족하는 단어가 없으면 보너스 화면을 건너뛴다. (3개 미만이어도 1개 이상이면 제시한다.)
- [ ] 화면에 "[보너스 도전하기] / [건너뛰기]" 버튼 표시
- [ ] 도전 선택 시 보너스 퀴즈 진행 (is_bonus = true로 기록)
- [ ] 건너뛰기 선택 시 완료 화면으로 이동
- [ ] 보너스 진도 반영: 보너스 결과는 Quiz 기록에만 남기고 Progress(정답·오답 횟수, 연속 정답, 복습 예정일, 상태)는 바꾸지 않는다.

**성공 기준**:
- 보너스 문제 정확하게 선정됨 (기본 퀴즈와 중복 없음)
- 조건을 만족하는 단어가 없을 때 보너스 화면이 나타나지 않음
- 선택사항 정상 작동
- 보너스 결과가 진도율에 영향을 주지 않음

---

#### FR-3.5: 퀴즈 완료 및 결과 화면
**목적**: 퀴즈 완료 후 결과 표시

**결과 화면**

**상세 요구사항**:
- [ ] 결과 표시:
  - 정답 개수 / 전체 개수
  - 정답률 (%)
  - 오늘 완료 문항 수 (예: "오늘 10/10 완료")
  - 전체 진도: 학습 완료 단어 수 / 전체 단어 수 (예: "975/1,500")
- [ ] 액션 버튼:
  - [다시 풀기]: 오늘 퀴즈 재진행 (is_retry 규칙은 FR-3.3-A 적용)
  - [단어 관리]: 단어 탭으로 이동
  - [홈으로]: 홈 화면으로 이동

**성공 기준**:
- 결과 정확하게 표시됨
- 버튼 정상 작동

---

#### FR-3.6: 퀴즈 세션 중단 및 재개 (v1.1 추가)
**목적**: 퀴즈 도중 앱을 닫아도 진행 상황을 잃지 않음

**상세 요구사항**:
- [ ] 세션 시작 시 문항 목록과 현재 위치를 DB의 `QuizSession` 테이블(단일 레코드)에 저장한다
- [ ] 문항에 답할 때마다 기록(Quiz, Progress 반영 규칙)을 즉시 저장한다. 중단 전 답변은 취소되지 않는다.
- [ ] 앱 재실행 후 홈 화면에 "이어서 풀기"를 표시한다.
- [ ] 세션이 끝나면 저장된 세션 정보를 삭제한다.
- [ ] 같은 날 날짜가 바뀌어 세션이 자정을 넘긴 경우, 세션은 시작한 날짜 기준으로 이어 풀되 새로 시작하는 퀴즈는 오늘 기준으로 구성한다.

**성공 기준**:
- 퀴즈 도중 앱을 종료하고 재실행하면 "이어서 풀기"로 남은 문항부터 진행된다.
- 중단 전 답변이 Quiz 기록에 남아 있다.

### 2.4 학습 진도 추적 기능

#### 상태 규칙 및 간격 반복 규칙 (FR-4.0)

**연속 정답 기반 간격**: 정답이 이어질수록 복습 간격을 늘린다.

| 연속 정답 (정답 반영 후) | 다음 복습까지 |
|---|---|
| 1회 | 1일 후 |
| 2회 | 3일 후 |
| 3회 | 7일 후 |
| 4회 | 14일 후 |
| 5회 이상 | 30일 후 |

- 오답이면 연속 정답을 0으로 되돌리고, 다음 복습은 1일 후로 한다.
- 다음 복습 예정일 = 반영한 날짜 + 간격.

**상태 판정 순서** (위에서부터 먼저 맞는 상태로 정한다):
1. 시도 횟수가 0 → `미학습`
2. 연속 정답 5회 이상 → `숙달`
3. 마지막 결과가 오답이거나, 복습 예정일이 오늘보다 이전 → `복습필요`
4. 그 밖의 경우 → `학습중`

---

#### FR-4.1: 홈 화면 대시보드 표시
**목적**: 학생이 학습 현황을 한눈에 파악

**화면**: 홈 탭 (기본 탭)

**상세 요구사항**:
- [ ] 학습 현황 표시:
  - 전체 진도율 (%) = 학습 완료 단어 수 ÷ 전체 단어 수 × 100, 진행 바로 표시
  - 등록된 전체 단어: X개
  - 학습 완료 단어: Y개 (상태가 `숙달`인 단어 수)
  - 오늘 학습할 단어: Z개 (오늘 구성된 퀴즈 문항 수, 퀴즈 시작 전에는 설정값 N)
- [ ] 분야별 진도 (토글 가능):
  - 각 분야의 진도율 (%), 진행 바
- [ ] 최근 활동:
  - 어제 완료 문항 수
  - 오늘 진행 상황 (오늘 완료 문항 수 / 오늘 구성 문항 수)
- [ ] 빠른 액션:
  - [퀴즈 시작하기] 버튼 (이어서 풀기 세션이 있으면 [이어서 풀기] 표시, FR-3.6)
  - [단어 관리] 버튼
  - [설정] 버튼

**성공 기준**:
- 모든 수치가 정확함
- 진행 바가 시각적으로 표시됨
- 버튼 정상 작동

---

#### FR-4.2: 단어별 상세 진도 정보
**목적**: 각 단어의 학습 상태를 자세히 확인

**화면**: 단어 관리 탭

**상세 요구사항**:
- [ ] 테이블 열:
  - 단어 (영어)
  - 상태 (미학습/학습중/복습필요/숙달)
  - 습득도 (%) - 정답률 (시도 0이면 `-`)
  - 마지막 복습일
  - 정답/시도 (예: "7/10")
- [ ] 행을 클릭하면 상세 보기:
  - 예문들 표시
  - 통계 (정답 횟수, 오답 횟수, 연속 정답, 다음 복습 예정일)
  - 수정 버튼 (FR-1.7), 삭제 버튼 (FR-1.4)

**성공 기준**:
- 모든 정보 정확하게 표시됨
- 상세 보기 정상 작동

## 6. 비즈니스 규칙

| 규칙 | 설명 |
|------|------|
| **간격 반복** | 정답/오답에 따라 consecutive_correct와 next_review_date를 2.4 규칙대로 계산 |
| **상태 전이** | 2.4의 상태 판정 순서대로 자동 변경 |
| **진도 반영** | 같은 날 첫 세션의 문항만 Progress에 반영. 다시 풀기·보너스 결과는 Quiz 기록만 남김 (FR-3.3-A, FR-3.4) |
| **보너스 조건** | 정답률 < 60% AND 마지막 복습일이 7일 이상 전 (기본 퀴즈와 중복 제외, 기본 퀴즈와 뜻이 같은 단어도 제외 — FR-3.4) |
| **동의어 중복 방지** | 한 퀴즈 세션(기본 퀴즈 + 보너스)에서 같은 한글 뜻의 단어는 한 번만 출제한다 (FR-3.1-F, FR-3.4, 설계서 ADR-08) |
| **분야** | 일상 / 비즈니스 / 미분류 3개로 고정. 사용자 정의 분야 신설은 v1.2 이후 검토 |
| **분야 최소 단어 수** | 분야 신설을 허용하게 되면 새 분야는 최소 50개 단어가 필요. v1.1에서는 신설이 없으므로 적용하지 않음 |
| **중복 방지** | 같은 영어 단어(공백·대소문자 무시)는 중복 추가 불가 (FR-1.7-A) |
| **날짜 기준** | "오늘"은 시스템 로컬 시간 기준이며 자정(00:00)에 바뀐다. 복습 예정일과 "7일 이상" 계산도 이 날짜를 쓴다 |
| **설정 적용 시점** | 설정 저장은 즉시 화면에 반영하고, 퀴즈 구성 값은 다음 "퀴즈 시작"부터 적용 (FR-2.1, FR-2.2) |

## 7. 인수 기준 (Acceptance Criteria)

### 각 기능별 인수 기준

**FR-3.1 오늘의 퀴즈 구성**:
- [ ] N개 문제 정확히 생성됨 (단어 부족 안내 시 제외)
- [ ] 신규·약한 단어 비율 50~70%
- [ ] 복습 대상 비율 20~30%
- [ ] 자주 틀린 단어 비율 10~20%
- [ ] 보기가 4개 모두 표시됨 (보기 후보 부족 시 문항 제외)

**FR-3.3 채점 및 진도 반영**:
- [ ] 정답 시 연속 정답 +1, 오답 시 0으로 초기화
- [ ] 같은 날 다시 풀기 후 Progress 수치가 변하지 않음

**FR-3.4 보너스**:
- [ ] 보너스 문제가 기본 퀴즈와 겹치지 않음
- [ ] 보너스 결과가 Progress에 반영되지 않음

**FR-1.7 단어 수정**:
- [ ] 공백·대소문자만 다른 영어로 수정하면 중복 경고가 표시됨

**FR-1.8 백업 및 복구**:
- [ ] 복구 전에 현재 DB가 자동 백업됨

**FR-3.6 세션 재개**:
- [ ] 퀴즈 도중 종료 후 재실행 시 "이어서 풀기"로 남은 문항부터 진행됨
