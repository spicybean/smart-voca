## 1. 개요

스마트보카는 SQLite 데이터베이스를 사용합니다. 총 7개의 테이블로 구성됩니다.

### 1.1 테이블 목록

| 테이블 | 설명 | 레코드 수 (초기) |
|--------|------|-----------------|
| Word | 학습 단어 | 1,500 |
| Example | 단어별 예문 | 3,000~5,000 |
| Progress | 학생의 단어별 학습 진도 (단어당 1행) | 1,500 |
| Quiz | 퀴즈 풀이 기록 | 동적 증가 |
| QuizSession | 진행 중인 퀴즈 세션 (재개용, 단일 레코드) | 0~1 |
| Settings | 학생 학습 설정 | 1 |
| DBVersion | DB 버전 관리 | 1 |

### 1.2 v1.0 대비 변경 사항 요약

| 구분 | 변경 내용 | 근거 (요구사항) |
|------|----------|----------------|
| Word | `is_deleted` 제거 (하드 삭제) | FR-1.4 CASCADE 삭제 |
| Word | `category` 값에 `미분류` 추가, CHECK 제약 추가 | 1.1 분야 정의 |

| Progress | 상태 전이 규칙을 2.4 판정 순서로 교체 | FR-4.0 |

| QuizSession | 신규 테이블 | FR-3.6 세션 재개 |
| Settings | `daily_word_count` 범위를 1~50으로 제한 | FR-2.2 |

| 전체 | 외래키 동작을 위해 `PRAGMA foreign_keys = ON` 필수 | FR-1.4 CASCADE |

## 2. 테이블 상세 정의

### 2.1 Word 테이블

**목적**: 학습 대상 영단어 저장

**SQL 스키마**:
```sql
CREATE TABLE Word (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    english VARCHAR(100) NOT NULL UNIQUE COLLATE NOCASE,
    korean_meaning VARCHAR(100) NOT NULL,
    category VARCHAR(20) NOT NULL DEFAULT '미분류' CHECK(category IN ('일상', '비즈니스', '미분류')),
    level INTEGER NOT NULL DEFAULT 1 CHECK(level BETWEEN 1 AND 5),
    created_date DATETIME NOT NULL DEFAULT (datetime('now', 'localtime')),
    updated_date DATETIME NOT NULL DEFAULT (datetime('now', 'localtime'))
);

CREATE INDEX idx_word_category ON Word(category);
```

**필드 정의**:

| 필드명 | 타입 | 제약조건 | 설명 |
|--------|------|---------|------|
| id | INTEGER | PK, AI | 고유 ID |
| english | VARCHAR(100) | NOT NULL, UNIQUE, COLLATE NOCASE | 영문 단어. 대소문자 무시 중복 불가. 앱에서 앞뒤 공백을 제거한 뒤 저장 |
| korean_meaning | VARCHAR(100) | NOT NULL | 한글 뜻 |
| category | VARCHAR(20) | NOT NULL, DEFAULT '미분류', CHECK | 분야 (일상 / 비즈니스 / 미분류) |
| level | INTEGER | NOT NULL, DEFAULT 1, CHECK(1~5) | 난이도 (CSV `level` 열과 동일). 미입력 시 1 |
| created_date | DATETIME | NOT NULL, 로컬 시간 | 생성일시 |
| updated_date | DATETIME | NOT NULL, 로컬 시간 | 수정일시 (FR-1.7) |

**인덱스 참고**: `english`는 UNIQUE 제약이 자동으로 인덱스를 만들므로 별도 인덱스를 두지 않습니다.

**샘플 데이터**:
```
id | english   | korean_meaning | category | level | created_date
1  | apple     | 사과           | 일상     | 1     | 2026-10-28 09:00:00
2  | banana    | 바나나         | 일상     | 1     | 2026-10-28 09:00:00
3  | interview | 면접           | 비즈니스 | 2     | 2026-10-28 09:00:00
```

### 2.2 Example 테이블

**목적**: 각 단어별 예문 저장. 기본 예문은 CSV에서 적재하고, 추가 예문은 학생이 입력한다 (FR-1.5, FR-1.6).

**SQL 스키마**:
```sql
CREATE TABLE Example (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    word_id INTEGER NOT NULL,
    sentence VARCHAR(500) NOT NULL,
    source VARCHAR(10) NOT NULL DEFAULT 'builtin' CHECK(source IN ('builtin', 'user')),
    created_date DATETIME NOT NULL DEFAULT (datetime('now', 'localtime')),
    FOREIGN KEY (word_id) REFERENCES Word(id) ON DELETE CASCADE
);

CREATE INDEX idx_example_word_id ON Example(word_id);
```

**필드 정의**:

| 필드명 | 타입 | 제약조건 | 설명 |
|--------|------|---------|------|
| id | INTEGER | PK, AI | 고유 ID |
| word_id | INTEGER | NOT NULL, FK | Word 테이블 참조 |
| sentence | VARCHAR(500) | NOT NULL | 예문 텍스트 |
| source | VARCHAR(10) | NOT NULL, DEFAULT 'builtin', CHECK | 출처 (builtin: CSV 기본 예문 / user: 학생 입력) |
| created_date | DATETIME | NOT NULL, 로컬 시간 | 생성일시 |

**중복 처리 참고**: 같은 `word_id`에 같은 `sentence`가 이미 있으면 INSERT하지 않습니다 (앱에서 검사). CSV 적재와 학생 입력 모두 적용합니다.

**샘플 데이터**:
```
id | word_id | sentence                          | source
1  | 1       | I eat an apple every day.         | builtin
2  | 1       | She put a red apple in her bag.   | builtin
3  | 1       | 사과를 깎고 있습니다.             | user
```

### 2.3 Progress 테이블

**목적**: 학생의 단어별 학습 진도 저장. 단어당 1행.

**SQL 스키마**:
```sql
CREATE TABLE Progress (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    word_id INTEGER NOT NULL UNIQUE,
    status VARCHAR(10) NOT NULL DEFAULT '미학습' CHECK(status IN ('미학습', '학습중', '복습필요', '숙달')),
    correct_count INTEGER NOT NULL DEFAULT 0,
    wrong_count INTEGER NOT NULL DEFAULT 0,
    consecutive_correct INTEGER NOT NULL DEFAULT 0,
    correct_rate REAL DEFAULT NULL,
    last_reviewed_date DATE,
    next_review_date DATE,
    created_date DATETIME NOT NULL DEFAULT (datetime('now', 'localtime')),
    updated_date DATETIME NOT NULL DEFAULT (datetime('now', 'localtime')),
    FOREIGN KEY (word_id) REFERENCES Word(id) ON DELETE CASCADE
);

CREATE INDEX idx_progress_status ON Progress(status);
CREATE INDEX idx_progress_next_review ON Progress(next_review_date);
CREATE INDEX idx_progress_last_reviewed ON Progress(last_reviewed_date);
```

**필드 정의**:

| 필드명 | 타입 | 제약조건 | 설명 |
|--------|------|---------|------|
| id | INTEGER | PK, AI | 고유 ID |
| word_id | INTEGER | NOT NULL, UNIQUE, FK | Word 테이블 참조 (단어당 1행) |
| status | VARCHAR(10) | NOT NULL, DEFAULT '미학습', CHECK | 상태 (미학습 / 학습중 / 복습필요 / 숙달) |
| correct_count | INTEGER | NOT NULL, DEFAULT 0 | 정답 횟수 |
| wrong_count | INTEGER | NOT NULL, DEFAULT 0 | 오답 횟수 |
| consecutive_correct | INTEGER | NOT NULL, DEFAULT 0 | 연속 정답 횟수. 오답이면 0 |
| correct_rate | REAL | NULL 허용 | 정답률 (0~100). 시도 0이면 NULL |
| last_reviewed_date | DATE | NULL | 마지막 복습일 |
| next_review_date | DATE | NULL | 다음 복습 예정일 |
| created_date | DATETIME | NOT NULL, 로컬 시간 | 생성일시 |
| updated_date | DATETIME | NOT NULL, 로컬 시간 | 수정일시 |

**계산 규칙** (요구사항 FR-3.3, FR-4.0):

```
시도 횟수 = correct_count + wrong_count
correct_rate = correct_count / 시도 횟수 × 100   (시도 0이면 NULL)

정답 반영 시:  correct_count + 1, consecutive_correct + 1
오답 반영 시:  wrong_count + 1, consecutive_correct = 0
반영 시마다:   last_reviewed_date = 오늘 (로컬)

다음 복습 간격 (consecutive_correct 기준):
  1회 → 1일 후
  2회 → 3일 후
  3회 → 7일 후
  4회 → 14일 후
  5회 이상 → 30일 후
  오답 → 1일 후
next_review_date = 오늘 + 간격
```

**상태 판정 순서** (위에서부터 먼저 맞는 상태):

```
1. 시도 횟수 = 0                                  → 미학습
2. consecutive_correct >= 5                        → 숙달
3. 마지막 결과가 오답 OR next_review_date < 오늘     → 복습필요
4. 그 밖의 경우                                    → 학습중
```

"마지막 결과가 오답"은 `consecutive_correct = 0`이고 `wrong_count > 0`이며 마지막 Quiz 기록이 오답인 경우로 판단합니다. 앱은 상태를 갱신할 때 이 규칙으로 `status`를 다시 계산해 저장합니다.

**샘플 데이터**:
```
id | word_id | status   | correct | wrong | consec | rate | last_reviewed | next_review
1  | 1       | 학습중   | 5       | 2     | 1      | 71.4 | 2026-10-27    | 2026-10-28
2  | 2       | 복습필요 | 3       | 2     | 0      | 60.0 | 2026-10-26    | 2026-10-27
3  | 3       | 미학습   | 0       | 0     | 0      | NULL | NULL          | NULL
```

### 2.4 Quiz 테이블

**목적**: 퀴즈 풀이 기록 저장. 통계와 재풀이 판정에 사용.

**SQL 스키마**:
```sql
CREATE TABLE Quiz (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    word_id INTEGER NOT NULL,
    quiz_type VARCHAR(10) NOT NULL CHECK(quiz_type IN ('한→영', '영→한')),
    is_correct BOOLEAN NOT NULL,
    is_bonus BOOLEAN NOT NULL DEFAULT 0,
    is_retry BOOLEAN NOT NULL DEFAULT 0,
    created_date DATETIME NOT NULL DEFAULT (datetime('now', 'localtime')),
    FOREIGN KEY (word_id) REFERENCES Word(id) ON DELETE CASCADE
);

CREATE INDEX idx_quiz_word_id ON Quiz(word_id);
CREATE INDEX idx_quiz_created_date ON Quiz(created_date);
```

**필드 정의**:

| 필드명 | 타입 | 제약조건 | 설명 |
|--------|------|---------|------|
| id | INTEGER | PK, AI | 고유 ID |
| word_id | INTEGER | NOT NULL, FK | Word 테이블 참조 |
| quiz_type | VARCHAR(10) | NOT NULL, CHECK | 문제 유형 (한→영 / 영→한) |
| is_correct | BOOLEAN | NOT NULL | 정답 여부 (1 = 정답) |
| is_bonus | BOOLEAN | NOT NULL, DEFAULT 0 | 보너스 문제 여부 |
| is_retry | BOOLEAN | NOT NULL, DEFAULT 0 | 같은 날 다시 풀기 여부 (FR-3.3-A) |
| created_date | DATETIME | NOT NULL, 로컬 시간 | 풀이 일시 |

**재풀이 판정 규칙** (파생 판정, 별도 컬럼 없음):
- 퀴즈 세션을 시작할 때 오늘 Quiz 기록 중 `is_bonus = 0 AND is_retry = 0` 행이 있으면 재풀이 세션이다.
- 재풀이 세션의 모든 답변은 `is_retry = 1`로 저장하고 Progress는 갱신하지 않는다.

**통계 제외 규칙**: 오늘·어제 완료 수, 정답률 등 기본 퀴즈 통계는 `is_bonus = 0 AND is_retry = 0`인 행만 센다.

**샘플 데이터**:
```
id | word_id | quiz_type | is_correct | is_bonus | is_retry | created_date
1  | 1       | 한→영     | 1          | 0        | 0        | 2026-10-28 14:30:00
2  | 2       | 영→한     | 0          | 0        | 0        | 2026-10-28 14:31:00
3  | 5       | 한→영     | 1          | 1        | 0        | 2026-10-28 14:35:00
4  | 1       | 한→영     | 1          | 0        | 1        | 2026-10-28 16:10:00
```

### 2.5 QuizSession 테이블 (신규)

**목적**: 퀴즈 도중 앱이 종료되었을 때 남은 문항부터 이어 풀기 위한 세션 정보 (FR-3.6). 세션이 끝나면 행을 삭제한다.

**SQL 스키마**:
```sql
CREATE TABLE QuizSession (
    id INTEGER PRIMARY KEY CHECK(id = 1),
    session_date DATE NOT NULL,
    phase VARCHAR(10) NOT NULL CHECK(phase IN ('basic', 'bonus')),
    is_retry BOOLEAN NOT NULL DEFAULT 0,
    total_count INTEGER NOT NULL CHECK(total_count >= 1),
    current_index INTEGER NOT NULL DEFAULT 0,
    items_json TEXT NOT NULL,
    started_at DATETIME NOT NULL DEFAULT (datetime('now', 'localtime'))
);
```

**필드 정의**:

| 필드명 | 타입 | 제약조건 | 설명 |
|--------|------|---------|------|
| id | INTEGER | PK, CHECK(id=1) | 항상 1 (단일 레코드) |
| session_date | DATE | NOT NULL | 세션 시작 날짜 (자정을 넘겨도 이 날짜 기준으로 이어 푼다) |
| phase | VARCHAR(10) | NOT NULL, CHECK | 진행 단계 (basic: 기본 퀴즈 / bonus: 보너스) |
| is_retry | BOOLEAN | NOT NULL, DEFAULT 0 | 재풀이 세션 여부 |
| total_count | INTEGER | NOT NULL, CHECK(>=1) | 세션 문항 수 |
| current_index | INTEGER | NOT NULL, DEFAULT 0 | 다음에 풀 문항 위치 (0부터) |
| items_json | TEXT | NOT NULL | 문항 목록 (JSON). 각 문항은 `word_id`, `quiz_type`, 보기 4개를 포함. 재개 시 보기가 바뀌지 않도록 생성 시점의 보기를 저장 |
| started_at | DATETIME | NOT NULL, 로컬 시간 | 세션 시작 시각 |

**items_json 예시**:
```json
[
  {"word_id": 1, "quiz_type": "한→영", "options": ["apple", "banana", "bridge", "cloud"], "answer_index": 0},
  {"word_id": 2, "quiz_type": "영→한", "options": ["바나나", "사과", "다리", "구름"], "answer_index": 0}
]
```

**재개 규칙**:
- 행이 있으면 홈 화면에 "이어서 풀기"를 표시한다.
- 재개 시 `items_json`의 `word_id` 중 Word에서 삭제된 단어는 건너뛴다.
- 세션 완료 또는 "그만하기" 선택 시 행을 삭제한다. "그만하기"는 세션을 지우지만 이미 제출한 Quiz 기록은 남긴다. 앱 종료 시에는 행을 지우지 않아 다음 실행 때 이어서 풀 수 있다.
- 기본 퀴즈가 끝나고 보너스를 제시하면 `phase`를 `bonus`로 바꾸고 `items_json`을 보너스 문항으로 교체한다.

### 2.6 Settings 테이블

**목적**: 학생의 학습 설정 저장 (단일 레코드)

**SQL 스키마**:
```sql
CREATE TABLE Settings (
    id INTEGER PRIMARY KEY CHECK(id = 1),
    selected_category VARCHAR(10) NOT NULL DEFAULT '선택안함' CHECK(selected_category IN ('선택안함', '일상', '비즈니스')),
    daily_word_count INTEGER NOT NULL DEFAULT 10 CHECK(daily_word_count BETWEEN 1 AND 50),
    last_updated_date DATETIME NOT NULL DEFAULT (datetime('now', 'localtime'))
);

INSERT INTO Settings (id) VALUES (1);
```

**필드 정의**:

| 필드명 | 타입 | 제약조건 | 설명 |
|--------|------|---------|------|
| id | INTEGER | PK, CHECK(id=1) | 항상 1 (단일 레코드) |
| selected_category | VARCHAR(10) | NOT NULL, DEFAULT '선택안함', CHECK | 학습 분야 (선택안함 = 전체) |
| daily_word_count | INTEGER | NOT NULL, DEFAULT 10, CHECK(1~50) | 일일 학습 개수 (5 / 10 / 15 / 커스텀) |
| last_updated_date | DATETIME | NOT NULL, 로컬 시간 | 마지막 수정일시 |

**샘플 데이터**:
```
id | selected_category | daily_word_count | last_updated_date
1  | 비즈니스          | 10               | 2026-10-28 09:00:00
```

CREATE TABLE DBVersion (
    id INTEGER PRIMARY KEY CHECK(id = 1),

);

INSERT INTO DBVersion (id, version) VALUES (1, '1.1');

**필드 정의**:

| 필드명 | 타입 | 제약조건 | 설명 |

| created_date | DATETIME | NOT NULL, 로컬 시간 | 생성일시 |

## 3. 테이블 관계도 (ERD)

```
Word (1)
  ├─→ (1:N) Example
  ├─→ (1:1) Progress
  └─→ (1:N) Quiz

QuizSession (0~1)   단일 레코드, Word를 참조하지 않고 items_json에 word_id를 담음
Settings (1)        단일 레코드
DBVersion (1)       단일 레코드
```

**Mermaid ERD**:
```
Word {
  int id PK
  string english UK
  string korean_meaning
  string category
  int level
}

Example {
  int id PK
  int word_id FK
  string sentence
  string source
}

Progress {
  int id PK
  int word_id FK,UK
  string status
  int correct_count
  int wrong_count
  int consecutive_correct
  float correct_rate
  date last_reviewed_date
  date next_review_date
}

Quiz {
  int id PK
  int word_id FK
  string quiz_type
  boolean is_correct
  boolean is_bonus
  boolean is_retry
  datetime created_date
}

QuizSession {
  int id PK
  date session_date
  string phase
  boolean is_retry
  int total_count
  int current_index
  text items_json
}

Settings {
  int id PK
  string selected_category
  int daily_word_count
}

DBVersion {
  int id PK
  string version
}

Word ||--o{ Example : has
Word ||--|| Progress : has
Word ||--o{ Quiz : has
```

## 4. 주요 쿼리 패턴

모든 날짜 비교는 로컬 날짜 기준입니다 (`DATE('now', 'localtime')`).

### 4.1 오늘의 퀴즈 구성 (FR-3.1)

구성 순서는 **자주 틀린 단어 → 복습 대상 → 신규·약한 단어 → 나머지** 입니다. 각 단계에서 이미 뽑은 `word_id`는 `NOT IN`으로 제외합니다. 앱은 뽑힌 목록이 비어 있으면 `NOT IN` 조건을 생략합니다.

개수는 `N = daily_word_count`일 때 `자주 틀린 = floor(N × 0.10)`, `복습 = floor(N × 0.20)`, `신규·약한 = N − (자주 틀린 + 복습)`입니다.

분야 필터는 `selected_category`가 `선택안함`이 아닐 때만 `AND w.category = :category`를 붙입니다.

**① 자주 틀린 단어** (정답률 60% 미만, 마지막 복습 7일 이상 전):
```sql
SELECT w.id, w.english, w.korean_meaning, w.level FROM Word w JOIN Progress p ON w.id = p.word_id WHERE p.correct_rate < 60 AND p.last_reviewed_date <= DATE('now', 'localtime', '-7 days') AND w.id NOT IN (:picked_ids) ORDER BY p.correct_rate ASC, p.last_reviewed_date ASC LIMIT :limit_wrong;
```

**② 복습 대상** (복습 예정일이 오늘 이하, 오래 밀린 순):
```sql
SELECT w.id, w.english, w.korean_meaning, w.level FROM Word w JOIN Progress p ON w.id = p.word_id WHERE p.next_review_date <= DATE('now', 'localtime') AND w.id NOT IN (:picked_ids) ORDER BY p.next_review_date ASC LIMIT :limit_review;
```

**③ 신규·약한 단어** (시도 0이거나 정답률 70% 미만):
```sql
SELECT w.id, w.english, w.korean_meaning, w.level FROM Word w JOIN Progress p ON w.id = p.word_id WHERE (p.correct_count + p.wrong_count = 0 OR p.correct_rate < 70) AND w.id NOT IN (:picked_ids) ORDER BY RANDOM() LIMIT :limit_new;
```

**④ 부족분 보충** (①~③에서 N개를 못 채운 경우, 남은 단어 중 무작위):
```sql
SELECT w.id, w.english, w.korean_meaning, w.level FROM Word w WHERE w.id NOT IN (:picked_ids) ORDER BY RANDOM() LIMIT :limit_fill;
```

**부족분 처리 순서**: ①이 모자라면 남는 개수를 ③에 더하고, 그래도 모자라면 ②의 남은 몫을 ③과 ④로 채웁니다. 전체 Word 수가 N보다 적으면 문항 수를 Word 수로 줄이고 안내를 표시합니다.

분야가 `일상`이면 모든 쿼리에 `AND w.category = '일상'`을 넣습니다. 분야가 비어 있는 경우를 고려해 기본 `선택안함`은 필터를 생략합니다.

---

### 4.2 4지선다형 보기 생성 (FR-3.1-E)

보기는 정답 한글 뜻(`:answer_meaning`)과 같은 뜻을 가진 단어를 제외하고, 세 단계로 3개를 채웁니다.

**① 같은 분야 + 난이도 ±1**:
```sql
SELECT DISTINCT w.korean_meaning, w.english FROM Word w WHERE w.category = :category AND ABS(w.level - :level) <= 1 AND w.id <> :word_id AND w.korean_meaning <> :answer_meaning ORDER BY RANDOM() LIMIT 3;
```

**② 같은 분야 (난이도 조건 해제)**: ①에서 모자랄 때, 같은 쿼리에서 `ABS(...)` 조건만 빼고 `NOT IN (이미 뽑은 단어)`를 추가해 실행합니다.

**③ 전체 무작위**: ②에서도 모자랄 때, `category` 조건을 빼고 같은 방식으로 실행합니다.

**최종 확인**: 앱에서 한글 뜻 기준으로 중복을 제거하고, 3개가 안 채워지면 해당 문항을 퀴즈에서 제외합니다.

### 4.3 보너스 문제 선정 (FR-3.4)

기본 퀴즈에 나온 단어는 제외합니다. 최대 5개까지 선정하며, 결과가 없으면 보너스 화면을 건너뜁니다.

기본 퀴즈와 뜻이 같은 단어(예: hour와 time이 모두 '시간')도 제외합니다 (설계서 ADR-08). 같은 뜻 단어가 보너스에 다시 나오면 한 문항에 정답이 둘이 되기 때문입니다.

```sql
SELECT w.id, w.english, w.korean_meaning, w.level FROM Word w JOIN Progress p ON w.id = p.word_id WHERE p.correct_rate < 60 AND p.last_reviewed_date <= DATE('now', 'localtime', '-7 days') AND w.id NOT IN (:basic_ids) AND w.korean_meaning NOT IN (SELECT b.korean_meaning FROM Word b WHERE b.id IN (:basic_ids)) ORDER BY p.correct_rate ASC, p.last_reviewed_date ASC LIMIT 5;
```

### 4.4 홈 화면 통계 (FR-4.1)

**전체 진도율** (진도율 = 학습 완료 단어 ÷ 전체 단어 × 100):
```sql
SELECT COUNT(*) AS total_words, COUNT(CASE WHEN p.status = '숙달' THEN 1 END) AS completed_words FROM Word w JOIN Progress p ON w.id = p.word_id;
```

**분야별 진도** (홈 화면에 항상 표시):
```sql
SELECT w.category, COUNT(*) AS total_words, COUNT(CASE WHEN p.status = '숙달' THEN 1 END) AS completed_words FROM Word w JOIN Progress p ON w.id = p.word_id GROUP BY w.category;
```

**오늘 완료 문항 수** (기본 퀴즈만, 재풀이·보너스 제외):
```sql
SELECT COUNT(*) AS today_done FROM Quiz WHERE is_bonus = 0 AND is_retry = 0 AND DATE(created_date) = DATE('now', 'localtime');
```

**어제 완료 문항 수**:
```sql
SELECT COUNT(*) AS yesterday_done FROM Quiz WHERE is_bonus = 0 AND is_retry = 0 AND DATE(created_date) = DATE('now', 'localtime', '-1 day');
```

**오늘 학습할 단어 (Z)**: 퀴즈 시작 전에는 `Settings.daily_word_count`, 세션 진행 중에는 `QuizSession.total_count`를 사용합니다. 쿼리 대신 앱 상태 값으로 계산합니다.

## 5. 데이터 초기화 및 백업 전략

### 5.1 첫 실행 시 저장 정책

- **테이블**: Word, Example, Progress, Quiz, QuizSession, Settings, DBVersion을 만든다. 외래키 제약은 DB 연결마다 켠다 (`PRAGMA foreign_keys = ON`)
- **초기 데이터 원본**: `data/words_common.csv` (일상 1,000개), `data/words_business.csv` (비즈니스 500개). 열은 english, korean_meaning, category, level, example_1~3
- **검증 규칙**: category는 일상·비즈니스·미분류 중 하나, level은 1~5 정수, english 중복 없음
- **초기 저장 값**
  - 예문: `source = 'builtin'`, 단어당 최대 3행, 빈 칸은 건너뜀
  - 학습 기록: 미학습, 횟수 0, 연속 정답 0, 정답률 NULL
  - 설정: 선택안함, 일일 학습량 10
  - 스키마 버전: `DBVersion` = '1.1'
- 적재 절차(검증을 먼저 하는 순서, 한 트랜잭션, 실패 시 DB 파일 삭제)는 기능 프로세스 설계서 P-01을 따른다

### 5.2 백업 및 복구 (FR-1.8)

백업은 파일을 그대로 복사하지 않고 SQLite 백업 API를 사용합니다. 앱이 DB를 열고 있는 동안 복사하면 일관성이 깨질 수 있기 때문입니다.

수동 백업, 자동 백업, 복구 전 백업은 모두 `backups/` 폴더에 저장한다. 사용자는 저장 위치를 고르지 않으며, 복구할 백업 파일은 이 폴더 안에서 고른다 (2026-11-11 결정).

| 구분 | 파일명 | 보관 규칙 |
|------|--------|----------|
| 자동 백업 (앱 종료 시) | `backups/auto_YYYYMMDD_HHMMSS.db` | 최근 3개만 유지, 오래된 것부터 삭제 |
| 수동 백업 | `backups/manual_YYYYMMDD_HHMMSS.db` | 삭제하지 않음 |
| 복구 전 안전 백업 | `backups/pre_restore_YYYYMMDD_HHMMSS.db` | 삭제하지 않음 |

**복구 파일 검증 기준**: 선택한 파일이 SQLite 파일이고 `DBVersion` 테이블과 `Word` 테이블이 있어야 한다. 아니면 복구를 거부한다. 복구 절차(전 백업, 복사, 재연결, 버전 확인)는 기능 프로세스 설계서 P-15를 따른다.

## 7. 데이터 무결성

### 7.1 제약조건

| 제약조건 | 설명 |
|---------|------|
| PRIMARY KEY | 각 테이블의 id는 유일 |
| FOREIGN KEY | Word - Example / Progress / Quiz 관계 유지. 삭제 시 CASCADE. **연결마다 `PRAGMA foreign_keys = ON`을 실행해야 동작함** |
| UNIQUE | Word.english 중복 불가 (대소문자 무시). Progress.word_id 단어당 1행 |
| CHECK | category 3개 값, level 1~5, daily_word_count 1~50, Example.source, Progress.status, Quiz.quiz_type, QuizSession.phase |
| DEFAULT | 기본값 설정으로 NOT NULL 보장 |

### 7.2 시각 저장 규칙

- 모든 `DATETIME` 기본값은 `datetime('now', 'localtime')`을 사용한다. SQLite의 `CURRENT_TIMESTAMP`는 UTC라서 사용하지 않는다.
- 날짜 비교 컬럼(`last_reviewed_date`, `next_review_date`, `session_date`)은 `DATE` 타입(YYYY-MM-DD)으로 저장한다.

### 7.3 트랜잭션 관리

- **연결 규칙**: DB 연결마다 외래키 제약을 켠다 (`PRAGMA foreign_keys = ON`). 오류가 나면 롤백하고 다시 던진다.
- **답변 트랜잭션**: 퀴즈 답변 한 건의 저장 경계(Quiz 행, Progress, 세션 위치)는 기능 프로세스 설계서 P-09를 따른다. 재풀이·보너스 답변은 Quiz 행만 추가한다 (FR-3.3-A, FR-3.4).
