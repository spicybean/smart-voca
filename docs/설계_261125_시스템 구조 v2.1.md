**파일 위치**: `docs/설계_261125_시스템 구조 v2.0.md`
**작성일**: 2026-11-25
**버전**: v2.1
**설명**: 웹 앱(Flask)의 모듈 구성, 계층, 요청 흐름, 배포 구조, 설계 결정(ADR)을 정의한다. 요구는 요구사항 명세서 v2.0, 데이터는 데이터 설계서 v2.0, 화면은 UI 설계서 v2.0을 따른다.

## 1. 개요

- 서버 렌더링 웹 앱. 화면은 Jinja2 템플릿과 HTML 폼으로 만들고, 자바스크립트는 쓰지 않는다.
- 계층: 라우트(화면) → 서비스(규칙) → 모델(DB). 규칙은 서비스에 두고 라우트는 요청을 연결만 한다.
- 실행: 개발은 Flask 개발 명령, 서버 이미지는 gunicorn (`wsgi:app`)으로 띄운다.
- 데이터: SQLite 한 파일 (`DB_PATH`). 서버에서는 `/data/voca.db`.

## 3. 계층과 책임

| 계층 | 파일 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| 라우트 | `views.py` | 요청 값을 받아 서비스 호출, 결과로 화면이나 이동 응답 | 규칙 판단, DB 직접 조작 (단순 조회 제외) |
| 서비스 | `*_service.py` | 입력 검증, 규칙 계산, DB 저장과 조회 | 화면 그리기 |
| 모델 | `models.py` | 테이블과 관계 정의 | 규칙 |
| 설정 | `config.py` | 환경변수 읽기 | 기본값 외의 판단 |

서비스는 Flask의 `db.session`을 쓰고 요청 객체를 받지 않는다. 그래서 테스트에서 앱 컨텍스트만 만들어 직접 호출할 수 있다.

## 4. 요청 흐름 (대표)

| 요청 | 라우트 | 서비스 | 응답 |
|---|---|---|---|
| 단어 추가 | `POST /words` | `word_service.add_word` | 목록으로 이동, 성공·실패 메시지 |
| CSV 가져오기 | `POST /words/import` | `word_service.import_csv` | 등록 결과 화면 (추가·중복·오류 줄) |
| 암기 카드 | `GET /memorize` | `study_service.day_word_ids`, `current_day` | 카드 화면 |
| 카드 응답 | `POST /memorize/answer` | `study_service.record_card` | 다음 카드로 이동 |
| 시험 시작 | `POST /exam/start` | `exam_service.create_session` | 첫 문항으로 이동 |
| 답 제출 | `POST /exam/<id>/answer` | `exam_service.answer_item` | 다음 문항 또는 결과 |
| 통계 | `GET /stats` | `stats_service.*` | 통계 화면 |

## 5. 규칙 설계

### 5.1 일차 구성 (`study_service.day_word_ids`)
- 단어를 id 순서로 정렬하고 하루 학습량씩 자른다.
- 복습: 이전 일차 단어에서 약 20%를 `random.Random(f"day-{n}")`으로 뽑는다. 같은 일차는 항상 같은 목록이다.
- 자주 틀린 단어: 시험 틀린 횟수가 많은 순 최대 3개를 일차 목록에 더한다 (중복 없음).

### 5.2 시험 출제 (`exam_service.pick_words`)
- 가중치 w: 안 본 단어 3.0, 본 단어 1.0 + min(지난 날수, 14)/7 + 0.5 × min(틀린 횟수, 5).
- 키 = 무작위수^(1/w), 키가 큰 순으로 문제 수만큼 고른다 (중복 없음).
- 방향 mix는 문항마다 무작위, 형식은 선택한 형식 중 무작위.
- 4지선다 보기가 4개 안 나오면 그 문항은 단답형으로 바꾼다.

### 5.3 채점 (`exam_service.answer_item`)
- mc: 보기 문자열과 정답 문자열이 같아야 정답.
- short: 정규화(소문자, 공백 정리, 끝 마침표 제거) 후 비교. 뜻은 구분자(`/ , ;`)로 나눠 한 조각이라도 맞으면 정답.
- ox: 제시한 뜻이 실제 뜻이면 정답 O, 다른 뜻이면 X. 응답이 기대값과 같으면 정답.

### 5.4 중복 단어 (`word_service.import_csv`)
- 키 = 공백 정리 후 소문자. DB에 있거나 파일 안에서 이미 나온 키면 건너뛴다.
- 형식 검사: 영단어 정규식, 뜻 필수, 열 2개 필수. 실패한 줄은 줄 번호와 사유를 보고한다.

## 6. 배포 구조

```
학교 서버 (인터넷 차단, UID 10001, 메모리 1GB)
  nginx (/2026/voca-<학번>/ 로 전달, 주소 치환)
     └── 컨테이너 voca-app
          gunicorn --bind 0.0.0.0:8080 --workers 2 wsgi:app
          DB_PATH=/data/voca.db (볼륨 /data, 소유 10001)
```

- 이미지: `python:3.13-slim` 기반, 의존성은 빌드 때 설치 (`requirements.txt`), 실행은 UID 10001.
- 로컬 검증 크기: 224MB (기준 500MB 이하).
- 점검: `docker-check.yml`이 빌드와 첫 화면 응답, 링크 경로, 재시작 후 데이터를 확인한다.

## 7. 설계 결정 기록 (ADR)

### ADR-01 플랫폼: 웹 앱 (Flask)
- **배경**: 기말과제 요건이 PC 크롬에서 동작하는 웹 앱을 학교 서버에 올리는 것이다.
- **대안**: PyQt6 데스크톱 유지 (과제 요건 불충족), 웹과 데스크톱 병행 (두 화면 관리 부담). FastAPI (비동기 불필요, 서버 렌더링 템플릿 지원은 Flask가 단순).
- **결정 근거**: 서버 템플릿과 폼으로 자바스크립트 없이 충분하다. 기존 서비스 계층(SQLAlchemy 동기 세션)을 그대로 쓸 수 있다.
- **재검토 조건**: 화면 상호작용이 복잡해져 자바스크립트가 많이 필요해질 때.
- **상태**: 채택. v1.x의 ADR-01(PyQt6)과 ADR-04(Windows 우선, exe 배포)는 대체됨.

### ADR-02 예문 출처: 외부 API 없음
- **배경**: 과제 제공 단어 CSV에 예문과 분야가 없다. 외부 사전 API는 키와 네트워크가 필요하다.
- **결정**: 외부 연동 없음. 예문 기능은 이번 버전에서 뺀다.
- **상태**: 채택 (v1.x ADR-02 유지, 예문 기능 자체는 제외).

### ADR-03 DB: SQLite, 경로는 환경변수
- **배경**: 과제 기본 DB는 SQLite이고, 서버 쓰기 위치는 `/data`뿐이다.
- **결정**: SQLite 파일 하나. `DB_PATH` 환경변수로 위치를 정하고, 기본은 `data/voca.db`.
- **상태**: 채택. PostgreSQL은 허락받지 않아 쓰지 않는다.

### ADR-04 서버 실행: gunicorn, exec 형식 CMD
- **배경**: 과제 규칙 R-14, R-15 (`flask run`, `--reload`, `debug` 금지).
- **결정**: `CMD ["gunicorn", "--bind", "0.0.0.0:8080", "--workers", "2", "wsgi:app"]`.
- **상태**: 채택.

### ADR-05 화면: 서버 렌더링, 자바스크립트 없음
- **배경**: 과제 권고 (서버 템플릿과 바닐라 JS로 충분). 상대 경로 규칙 R-04를 지키기 쉬워야 한다.
- **결정**: 모든 상호작용을 HTML 폼과 링크로 한다. 주소는 `/`로 시작하고 속성은 따옴표로 감싼다. 테스트로 검사한다.
- **상태**: 채택.

### ADR-06 로그인: 구현 (v2.1)
- **배경**: 도전 기능이며 필수 범위가 우선이다.
- **결정**: 비밀번호는 Werkzeug 해시로 저장하고, 세션에는 계정 번호만 둔다. 기록과 통계는 계정별로 계산한다. 다른 계정의 통계는 공개한 계정만 읽기 전용으로 본다. 단어는 모든 계정이 공유한다.
- **재검토 조건**: 외부 로그인(소셜 로그인 등)을 도입할 때.
- **상태**: 채택.
