## 2. 이미지 빌드
```
docker build -t voca-app .
```
- 기반 이미지: `python:3.13-slim` (버전 태그 명시, `latest` 금지)
- 순서: 의존성(`requirements.txt`) 먼저 설치 → 실행 사용자 UID 10001 생성 → `/data` 소유 10001 → 소스 복사
- 로컬 검증 결과: 224MB (기준 500MB 이하)
- 빌드 중 인터넷 사용. 실행 중에는 사용하지 않는다.

## 3. 실행
```
docker run --rm -p 8080:8080 -e SECRET_KEY=... -v voca-data:/data voca-app
```
- 명령: `gunicorn --bind 0.0.0.0:8080 --workers 2 wsgi:app` (exec 형식)
- 실행 사용자: UID 10001, 권한 제거 (`--cap-drop ALL`, `no-new-privileges`), 메모리 1GB
- DB: `DB_PATH=/data/voca.db`. 첫 실행 때 테이블 자동 생성.
- 환경변수: `SECRET_KEY` (없으면 실행할 때마다 무작위), `DB_PATH`. 비밀값은 이미지에 넣지 않는다.

## 4. 점검 워크플로
- 파일: `.github/workflows/docker-check.yml` (과제 제공 원본, 수정 금지, R-09)
- 실행: push와 수동 실행. 단계는 빌드 → 인터넷 차단 네트워크 → 첫 화면 응답(30초 안) → 첫 화면 링크 점검 → 재시작 후 응답과 `/data` 확인 → 이미지 크기
- 최신 결과: `2b8723f` success
- 제출 SHA: 초록 체크가 있는 커밋의 40자 SHA를 제출 폼에 적는다.

## 5. 데이터 위치
| 항목 | 위치 |
|---|---|
| DB | `/data/voca.db` (볼륨 `voca-data`) |
| 개발 DB | `data/voca.db` (`DB_PATH`로 변경 가능) |
| 백업 | 제공하지 않음. `/data` 볼륨을 보존한다 |
| 로그 | 표준 출력 (gunicorn 로그). `docker logs` 로 확인 |

## 6. 배포 검증 체크리스트
제출 전에 모두 확인한다. 하나라도 실패하면 제출하지 않는다.
- [ ] 자동 테스트 67건 이상 통과 (`pytest -q`)
- [ ] `docker build .` 성공, 크기 500MB 이하
- [ ] 로컬 컨테이너 실행 시 `/` 응답 200
- [ ] 재시작 후 응답과 데이터 유지
- [ ] `docker-check` 워크플로가 제출 커밋에서 success
- [ ] 리포가 Public 상태
- [ ] 리포 README에 구현 요구사항 ID 목록 포함
- [ ] 커밋 메시지와 문서에 실명·학번 없음 (과거 이력 제외, 2026-11-25 결정)

## 7. 장애 대응
| 장애 | 대응 |
|---|---|
| 점검 워크플로 실패 | Actions 로그의 실패 단계 확인. R-01~R-16 중 해당 규칙 수정 후 push |
| 컨테이너가 시작하지 않음 | `docker logs`로 오류 확인. 환경변수와 `/data` 권한 점검 |
| DB 파일 손상 | `/data`의 파일을 백업 후 삭제하면 다음 실행 때 새로 만든다 (기록은 사라짐) |
| 잘못된 커밋을 제출 | 새 커밋을 올리고 그 SHA를 제출. force-push 금지 (과제 규칙) |
