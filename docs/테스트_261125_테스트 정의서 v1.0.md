## 1. 목적과 범위
- 요구사항(VOCA-FR, VOCA-NFR)과 규칙이 테스트로 검증되는지 기준을 정한다.
- 자동 테스트: 서비스 규칙, 화면 흐름, 계정, CSRF, 서버 경로 규칙.
- 수동 검증: 크롬 화면, 서버 배포 실행 (7장).

## 2. 도구와 실행
| 항목 | 값 |
|---|---|
| 테스트 도구 | pytest 9.2.0 |
| 실행 명령 | `venv\Scripts\python.exe -m pytest -q` |
| DB | 테스트마다 임시 SQLite 파일 (`tmp_path`). `data/`를 건드리지 않음 |
| CSRF | 화면 흐름 테스트에서는 끔 (`CSRF_ENABLED=False`). CSRF 테스트에서는 켬 |
| 로그인 | 화면 테스트의 `client` fixture는 가입 후 로그인된 상태 |

## 4. 테스트 수준
| 수준 | 대상 | 방법 |
|---|---|---|
| 단위·서비스 | `app/*_service.py` | 함수 호출 후 DB 상태 확인 |
| 화면 흐름 | `app/views.py`, 템플릿 | 테스트 클라이언트로 요청, 응답과 이동 주소 확인 |
| 계정·보안 | `app/auth.py`, CSRF | 로그인 상태별 응답, 토큰 검사 |
| 규칙 | 템플릿 파일 | `/`로 시작하는 링크, 따옴표 속성 (R-04) |

## 8. 결과 기록 규칙
- 실행할 때마다 날짜, 명령, passed/failed 건수를 작업 일지에 남긴다.
- 실패하면 원인과 조치를 같은 일지에 적는다.
- 기준선(3장)은 테스트를 추가할 때마다 갱신한다.

## 9. 알려진 한계
- 화면 테스트는 HTML 응답을 확인한다. 실제 클릭 동작과 레이아웃은 M-1로 확인한다.
- 가중치 추첨은 확률적이므로, 테스트는 통계적으로 기대 방향을 확인한다.
