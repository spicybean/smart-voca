## 1. 프로젝트 개요

### 1.1 프로젝트명
**스마트보카 (Smart-Voca)** — 영단어 개인 학습 시스템

### 1.2 프로젝트 목표
학생이 **과학적 학습 방법(간격 반복)**과 **검수된 예문(기본 예문 + 학생 입력)**을 결합하여 영단어를 효율적으로 학습하는 환경을 제공한다.

---

## 2. 비즈니스 요구사항 (BRD)

### 2.1 문제 정의
- **기존 방식의 문제**: 전통적인 단어장 암기는 수동적이며, 복습 주기가 명확하지 않아 학습 효율이 낮음
- **목표 사용자**: 영단어 학습이 필요한 학생 (개인용 학습)
- **기대 효과**:
  - 학습 시간 단축 (효율적인 복습 일정)
  - 장기 기억 강화 (간격 반복)
  - 실제 표현 학습 (검수된 예문)

### 2.2 핵심 가치
1. **과학적 학습**: Ebbinghaus 망각곡선 기반 간격 반복 알고리즘
2. **신뢰성**: 단어당 검수된 기본 예문 3개를 제공하고, 학생이 예문을 직접 추가할 수 있음
3. **단순성**: 학생이 쉽게 사용할 수 있는 직관적 인터페이스

## 3. 시스템 범위 및 기능 (SS)

### 3.1 포함 기능 (In Scope)

#### v1.0 핵심 기능

| 기능명 | 설명 | 우선순위 |
|--------|------|----------|
| **단어 등록/관리** | 학생이 학습할 단어를 등록, 수정, 조회, 삭제 | 필수 |
| **예문 제공** | CSV 기본 예문(단어당 3개) 표시, 학생이 예문 직접 추가 | 필수 |
| **분야별 학습** | 분야(일상/비즈니스/미분류) 필터링 및 학습 분야 선택 | 필수 |
| **일일 학습 설정** | 일일 학습량(5/10/15/커스텀) 설정 | 필수 |
| **4지선다형 퀴즈** | 한→영, 영→한 양방향 4지선다형 문제 | 필수 |
| **보너스 문제** | 기본 퀴즈 완료 후 약한 단어 추가 출제 | 필수 |
| **학습 진도 추적** | 개인의 단어별 습득 상태 시각화 | 필수 |
| **데이터 백업·복구** | 학습 기록을 파일로 백업하고, 백업 파일로 복구 | 필수 |
| **퀴즈 세션 재개** | 퀴즈 도중 앱을 닫아도 남은 문항부터 이어서 풀기 | 필수 |

#### 기능 상세

**3.1.1 단어 등록/관리**
- **초기 데이터 로드**: 1,500개 사전 등록 단어 (CSV 기반, 앱 첫 실행 시 자동 로드)
  - 일상 영단어: 1,000개 (분야 `일상`)
  - 비즈니스/취업 단어: 500개 (분야 `비즈니스`)
- **분야**: `일상`, `비즈니스`, `미분류` 3개로 고정. 학생이 직접 등록한 단어는 기본 `미분류`
- **난이도**: 1~5 (CSV 미입력 시 1)
- 학생이 새 단어를 등록하고, 등록된 단어의 영어·뜻·분야·난이도를 수정할 수 있음
- 단어 목록 조회 (테이블 형식), 키워드 검색, 단어 삭제

**3.1.2 예문 제공**
- 초기 단어 1,500개는 CSV의 예문 3개를 함께 저장한다 (출처: builtin)
- 학생이 추가한 단어는 예문이 없으므로 직접 입력하도록 안내한다
- 학생이 직접 예문을 추가할 수 있다 (출처: user)
- 외부 사전 API를 쓰지 않으므로 인터넷 연결과 키가 필요 없다 (설계서 ADR-02)

**3.1.3 간격 반복 퀴즈**

- 4지선다형 문제만 사용하며, 한→영과 영→한을 50 : 50으로 출제한다
- 자주 틀린 단어, 복습 대상, 신규·약한 단어를 비율대로 뽑는다. 단어가 부족하면 문항 수를 줄이고 안내한다
- 학습 상태(미학습·학습중·복습필요·숙달)를 정하고, 연속 정답에 따라 다음 복습일을 정한다
- 구성 순서, 보기 선정, 상태 판정, 간격 규칙의 처리 절차는 **기능 프로세스 설계서 P-08, P-13**을 따른다. 규칙 수치는 **요구사항 FR-3.1, FR-4.0**을 따른다

**3.1.4 일일 학습 설정**
- **학습 분야 선택**: 일상 / 비즈니스 / 선택안함(전체)
- **일일 학습량 설정**: 5개 / 10개 / 15개 / 커스텀 (커스텀 선택 시 입력 필드 표시)
- 설정 저장은 즉시 화면에 반영하고, 퀴즈 구성 값은 다음 "퀴즈 시작"부터 적용한다. 진행 중인 세션은 시작 시점 값을 유지한다.

**3.1.5 보너스 문제**
- 기본 퀴즈를 끝내면 약한 단어를 최대 5개 제시한다. 학생이 도전하거나 건너뛸 수 있다
- 보너스 결과는 퀴즈 기록에만 남고, 단어의 진도에는 반영하지 않는다
- 대상 선정과 처리 순서는 **기능 프로세스 설계서 P-10**, 규칙은 **요구사항 FR-3.4**를 따른다

**3.1.6 학습 진도 추적**
- 대시보드:
  - 전체 단어 수
  - 학습 완료 단어 수 (상태가 `숙달`인 단어 수)
  - 오늘 학습할 단어 수
  - 전체 진도율 (%) = 학습 완료 단어 수 ÷ 전체 단어 수
- 단어별 상태 표시:
  - 상태 (미학습 / 학습중 / 복습필요 / 숙달)
  - 정답률 (%) — 시도 0이면 `-`
  - 마지막 복습일
  - 정답/시도 횟수
- 분야별 진도율 표시

**3.1.7 데이터 백업·복구**
- 수동 백업, 복구, 종료 시 자동 백업을 제공한다. 저장 위치는 백업 폴더(`backups/`)로 고정하며 학생이 고르지 않는다
- 복구 전에는 현재 데이터를 자동으로 백업한다
- 처리 절차와 검증 방식은 **기능 프로세스 설계서 P-15**, 규칙은 **요구사항 FR-1.8**, 파일 규칙은 **데이터 설계서 5.2**를 따른다

**3.1.8 퀴즈 세션 재개**
- 답은 한 건씩 즉시 저장하므로 중단해도 이전 답변은 남는다
- 중단한 퀴즈는 홈의 "이어서 풀기"로 재개한다. "그만하기"를 선택하면 세션을 삭제한다
- 처리 절차는 **기능 프로세스 설계서 P-12**, 규칙은 **요구사항 FR-3.6**을 따른다

## 4. 기술 스택

| 계층 | 기술 | 사유 |
|------|------|------|
| **언어** | Python 3.11+ | 빠른 개발, 많은 라이브러리 생태계 |
| **GUI 프레임워크** | PyQt6 | 순수 Python 개발, 데스크톱 UI. 확정 (시스템 구조 설계서 ADR-01) |

| **배포 및 빌드** | PyInstaller | Windows `.exe` 생성 (Mac `.app`은 후속 단계) |

## 6. 데이터 개요

### 6.1 주요 데이터

| 엔티티 | 설명 | 주요 속성 |
|--------|------|----------|
| **Word (단어)** | 학습 대상 단어 | id, english, korean_meaning, category (일상/비즈니스/미분류), level (1~5), created_date, updated_date |
| **Example (예문)** | 단어별 예문 | id, word_id, sentence, source (builtin / user) |
| **Progress (진도)** | 단어별 학습 진도 (단어당 1행) | id, word_id, status, correct_count, wrong_count, consecutive_correct, correct_rate, last_reviewed_date, next_review_date |
| **Quiz (퀴즈 기록)** | 퀴즈 풀이 기록 | id, word_id, quiz_type (한→영 / 영→한), is_correct, is_bonus, is_retry, created_date |
| **QuizSession (진행 중 세션)** | 퀴즈 도중 종료 시 이어 풀기용 세션 정보 (세션 종료 시 삭제) | session_date, phase, total_count, current_index, items |
| **Settings (설정)** | 학생 학습 설정 (단일 레코드) | selected_category (선택안함 / 일상 / 비즈니스), daily_word_count (1~50), last_updated_date |

- 상세 컬럼과 제약조건은 데이터 설계서 v1.8을 따른다.

### 6.2 데이터 저장소
- **SQLite 파일**: 사용자 데이터 폴더에 저장한다.
  - Windows: `%APPDATA%\SmartVoca\smart_voca.db`
  - macOS: `~/Library/Application Support/SmartVoca/smart_voca.db`
- 배포 파일에는 DB를 포함하지 않는다. 학습 기록은 사용자 폴더에 남는다.
- **CSV 파일** (초기 데이터, 프로젝트 `data/` 폴더):
  - `data/words_common.csv` (일상 단어 1,000개)
  - `data/words_business.csv` (비즈니스 단어 500개)

### 6.3 초기 데이터 로드
- 앱 첫 실행 시 DB가 없으면 CSV 1,500개 단어를 자동 로드하고, 모든 단어를 `미학습` 상태로 초기화한다.
- 절차와 실패 처리는 데이터 설계서 5.1을 따른다.

## 7. 제약사항 및 가정

### 7.1 제약사항

#### 기술적 제약
1. **외부 서비스 없음**: 사전 API를 쓰지 않으므로 인터넷 연결과 외부 API 한도 제약이 없다
2. **예문 범위**: 기본 예문은 CSV에 있는 단어만 가진다. 새로 추가한 단어는 학생이 예문을 입력해야 한다
3. **단일 사용자**: SQLite 사용으로 동시 다중 사용자 미지원
   - v1.0: 단일 계정만 지원
   - v2.0: 다중 사용자 지원 예정

#### 기능적 제약
4. **초기 데이터 필수**: 앱 사용을 위해 1,500개 단어 CSV 필요

#### 배포 관련 제약
5. **설치 필수**: PyQt 데스크톱 앱이므로 exe 파일(또는 후속 단계의 app 파일) 실행 필요
6. **플랫폼별 빌드**: Windows는 `.exe`, Mac은 `.app`을 각각 빌드해야 하며, Windows 환경에서는 `.app`을 만들 수 없음
7. **Python 설치 불필요**: 최종 사용자는 Python 설치 불필요 (exe/app에 포함)
8. **라이선스**: PyQt6는 GPL 라이선스이며, 배포 방식 확정 시 조건을 다시 검토한다 (설계서 12장)

### 7.2 가정
1. 개발자는 Python 실행 환경이 있는 노트북에서 개발한다. 최종 사용자는 Python이 없어도 된다.
2. CSV 기본 예문 1,500개 × 3문장은 학습에 충분한 품질이다 (샘플 검수 기준, 전수 검수는 하지 않음)

## 10. 운영 가이드

### 10.1 빌드 및 배포

**필요한 도구**: `pip install pyinstaller`

**빌드 대상**:
- Windows: `dist/SmartVoca.exe` 생성 (1차 배포 대상)
- Mac: `dist/SmartVoca.app` 생성 (후속 단계, Mac 환경에서 빌드)

- `--add-data`에는 CSV만 포함하고 DB 파일은 포함하지 않는다 (설계서 ADR-03). `data/` 폴더 전체를 넣으면 개발용 DB가 함께 묶이므로, CSV 파일을 하나씩 지정한다 (Windows 구분자는 `;`).
  - 예: `--add-data "data/words_common.csv;data" --add-data "data/words_business.csv;data"`
- 배포는 exe 파일 1개를 직접 전달하는 방식으로 한다. 설치 프로그램(installer)은 제작하지 않는다.

### 10.2 외부 연동

외부 API와 API 키를 쓰지 않는다. 비밀값이 필요해지면 설계서를 먼저 고친 뒤 추가한다 (설계서 ADR-02).

### 10.3 예문 저장 전략
- CSV 기본 예문은 초기 DB 생성 시 Example 테이블에 `source = builtin`으로 저장한다.
- 학생이 직접 입력한 예문은 `source = user`로 구분하여 저장한다.

### 10.4 에러 처리 전략

- 시나리오별 대응 (예문 없음, CSV 손상, DB 손상 등)은 **기능 프로세스 설계서 5장**으로 옮겼다.

## 11. 배포 및 초기화 절차

### 11.1 개발 환경
1. 의존성 설치 후 `python ai-agent/scripts/init_db.py` 실행 (DB 초기화, 최초 1회)
2. `python src/main.py`로 앱 실행
- 개발 폴더 구조는 설계서 3장을 따른다.

### 11.2 배포 (최종 사용자)
1. 개발자가 `SmartVoca.exe`를 빌드하여 전달
2. 사용자가 exe를 실행
3. 첫 실행 시 사용자 데이터 폴더에 DB를 자동 생성하고 초기화
4. 설정 화면에서 학습 분야와 일일 학습량을 정하고 학습 시작

- 첫 실행 화면의 흐름과 화면 구성은 UI 설계서 3장을 따른다.

## 12. 테스트 전략

### 12.1 단위 테스트
- 간격 반복 규칙 (연속 정답별 간격, 오답 시 초기화)
- 상태 판정 순서
- 퀴즈 구성 개수 계산과 부족 시 채우기
- 보기 선정 순서와 정답 뜻 중복 제외
- 보너스 대상 선정 (조건, 우선순위, 최대 5개)

테스트 파일과 항목 상세는 설계서 8장을 따른다.

### 12.2 통합 테스트
- 설정 저장 → 오늘의 퀴즈 구성 → 퀴즈 풀이 → 진도 반영 → 보너스 제시 순서로 전체 흐름을 확인한다.
- 퀴즈 도중 종료 후 재실행 시 "이어서 풀기"로 남은 문항부터 이어지는지 확인한다.

### 12.3 수동 테스트

| 시나리오 | 검증 항목 | 기대 결과 |
|---------|----------|----------|
| **첫 실행** | DB 초기화, 1,500개 단어 로드 | 로드 완료, 진도 0% |
| **설정 저장** | 분야/일일량 저장 | 다음 퀴즈 시작부터 반영 |
| **퀴즈 풀이** | 설정 개수만큼 문제 제시, 채점 | 정답률 계산, 진도 업데이트 |
| **보너스 문제** | 기본 퀴즈 후 제시 | 조건 만족 단어 최대 5개 제시, 없으면 건너뜀 |
| **보너스 진도** | 보너스 정답/오답 후 진도 확인 | 진도 변화 없음 (기록만 남음) |
| **간격 반복** | 복습 일정 업데이트 | 연속 정답 수에 따른 간격 적용 |
| **백업·복구** | 백업 만들기 → 데이터 변경 → 백업에서 복구 | 복구 후 백업 시점의 데이터와 같음, 복구 전 자동 백업 생성 |
| **세션 재개** | 퀴즈 중간 종료 후 재실행 | "이어서 풀기"로 남은 문항부터 진행 |

## 부록: 용어 정의

| 용어 | 정의 |
|------|------|
| **간격 반복** | Ebbinghaus 망각곡선에 따라 연속 정답 수에 맞춰 복습 간격을 늘려나가는 학습법 |
| **기본 예문** | CSV에 들어 있는 단어별 예문 3개 (source = builtin) |
| **정답률** | 정답 횟수 ÷ 시도 횟수 × 100 (시도 0이면 없음) |
| **숙달** | 연속 정답 5회 이상인 상태 |
| **CSV 초기 데이터** | 앱 첫 실행 시 DB에 자동으로 로드되는 사전 등록 단어 |
| **init_db.py** | CSV 파일을 읽어 SQLite DB에 데이터를 로드하는 초기화 스크립트 |
| **4지선다형** | 4개의 보기 중 정답을 고르는 객관식 문제 유형 |
| **양방향 퀴즈** | 한→영과 영→한 두 방향 모두 출제되는 문제 |
| **보너스 문제** | 기본 퀴즈 완료 후, 약한 단어와 오래된 단어로 구성된 추가 문제. 진도에는 반영되지 않음 |
| **오늘의 퀴즈 구성** | 신규·약한 단어 + 복습 대상 + 자주 틀린 단어 조합 (설정된 개수) |
| **분야** | 단어의 학습 구분 (일상 / 비즈니스 / 미분류) |
