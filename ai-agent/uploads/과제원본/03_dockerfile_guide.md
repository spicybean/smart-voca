# Dockerfile 구성 — 학교 서버에 올리기

> v1.0 (2026-11-24). Dockerfile은 AI로 만들어도 됩니다. 「Dockerfile 생성 프롬프트」를 쓰세요. 그 결과가 아래 규칙을 지키는지는 **점검 워크플로**로 확인합니다.

## 1. 서버가 내 앱을 실행하는 방식

학교 서버는 내 리포의 `Dockerfile` 로 이미지를 만들고, 아래 조건으로 실행합니다.

| 조건 | 내 앱에 필요한 것 |
|---|---|
| 포트 8080으로 요청이 들어온다 | `0.0.0.0:8080` 에서 듣는다 (`localhost`·`127.0.0.1` 은 안 됨) |
| 주소 `/2026/voca-<학번>/` 아래에서 열린다 | 앱은 `/` 기준으로 만든다. 서버가 주소 앞부분을 떼고 넘긴다. 페이지 안의 링크·리다이렉트·쿠키 경로에는 다시 붙여 준다 |
| 사용자 UID 10001, 리눅스 권한 없이 실행한다 | 실행 중에 root 권한이 필요한 일을 하지 않는다 |
| 쓰기는 `/data`·`/tmp` 에만 된다 | SQLite 파일은 `/data/voca.db` 에 둔다 |
| 실행 중 인터넷이 막혀 있다 | 의존성은 빌드할 때 모두 설치한다 (브라우저가 CDN을 받는 것은 된다) |
| 비밀값은 환경변수로 준다 | `SECRET_KEY`, DB 접속 정보는 환경변수로 받는다 |
| 메모리는 1GB까지 | 보통의 웹 앱이면 충분하다 |

## 2. 리포에 둘 파일

```
내-리포/
├── Dockerfile                        ← 필수
├── .dockerignore                     ← 권장
├── .gitattributes                    ← 권장 (Windows 줄바꿈 문제 예방)
├── .github/workflows/docker-check.yml ← 필수. 내려받은 파일을 고치지 않고 넣는다
├── README.md
├── CLAUDE.md
├── docs/
└── (앱 코드)
```

## 3. 규칙

### 3.1 필수 — 어기면 서버에 올라가지 않습니다

| ID | 규칙 |
|---|---|
| R-01 | 리포 **루트**에 `Dockerfile` 이 있고, 루트에서 `docker build .` 한 번으로 이미지가 만들어진다 |
| R-02 | 공식 이미지에서 시작하고 **버전 태그를 적는다** (`python:3.13-slim` ○, `python` ×, `latest` ×) |
| R-03 | 앱은 **`0.0.0.0:8080`** 에서 듣는다 |
| R-04 | **앱은 `/` 를 기준으로 만든다.** 서버가 주소를 옮길 수 있도록 다음을 지킨다. ① 주소는 `/login` 처럼 `/` 로 시작하거나 `login` 처럼 상대 경로로 쓴다. ② HTML 속성은 따옴표로 감싼다 (`href="/login"` ○, `href=/login` ×). ③ JS에서는 `fetch("/api/words")` 처럼 **호출하는 자리에 문자열로** 쓴다 (`const API = "/api"` 처럼 앞부분을 변수로 빼지 않는다). ④ `http://localhost:8080` 같은 호스트를 코드에 쓰지 않는다. ⑤ 주소를 JSON 응답에 담아 내려 주지 않는다 |
| R-05 | **UID 10001로 실행해도 동작한다.** Dockerfile에서 UID 10001 사용자를 만들고 마지막 `USER` 로 지정한다. 실행 중에 `chown`, 패키지 설치, 1024 미만 포트 같은 root 권한 작업을 하지 않는다 |
| R-06 | **DB는 SQLite를 쓴다.** 파일 위치는 환경변수 `DB_PATH`(값 `/data/voca.db`)를 따른다. Dockerfile에서 `/data` 를 만들고 소유자를 10001로 한다. 처음 실행하면 테이블을 스스로 만든다. 실행 중 파일 쓰기는 `/data` 와 `/tmp` 에만 한다. *(PostgreSQL을 허락받은 경우: `DB_HOST`·`DB_PORT`·`DB_NAME`·`DB_USER`·`DB_PASS` 로 접속하고, DB가 늦게 뜰 수 있으니 접속을 재시도한다)* |
| R-07 | **실행 중 인터넷이 필요 없다.** 의존성은 빌드할 때 설치한다 |
| R-08 | **비밀값을 리포·이미지에 넣지 않는다.** 세션 키는 `SECRET_KEY` 환경변수로 받고, 없으면 기동할 때 무작위로 만든다. `.env` 는 커밋하지 않는다 |
| R-09 | **점검 워크플로를 고치지 않고 넣고, 제출 커밋에서 통과(초록)** 한다 |
| R-10 | **서버 빌드에서 거부되는 지시를 쓰지 않는다**: 첫 줄 `# syntax=` 지시어, `RUN --mount=type=ssh`·`RUN --mount=type=secret`, `RUN --network=…`, `RUN --security=…` |

### 3.2 권장 — 어기면 감점입니다

| ID | 규칙 |
|---|---|
| R-11 | `.dockerignore` 로 `.git`, `.venv`·`venv`, `node_modules`, `__pycache__`, `*.db`, `.env`, IDE 설정을 뺀다 |
| R-12 | `.gitattributes` 에 `* text=auto eol=lf` 를 둔다 |
| R-13 | 의존성 파일을 소스보다 먼저 COPY해서 설치한다. Python은 `requirements.txt`, Node는 `package-lock.json` + `npm ci` |
| R-14 | 운영용 서버로 띄운다 (Flask → `gunicorn`, FastAPI → `uvicorn`, Node → `node`). `flask run`·`--reload`·`debug=True`·`nodemon` 은 쓰지 않는다 |
| R-15 | `CMD` 는 exec 형식(`["…", "…"]`)으로 쓴다 |
| R-16 | 이미지 크기는 **500MB 이하** |

### 3.3 하지 않아도 되는 것

- 하위 경로(`/2026/voca-<학번>/`)에 맞추는 코드. 서버가 처리합니다. R-04만 지키면 됩니다.
- `docker-compose.yml`, HTTPS, 도메인, 포트 공개. 서버가 합니다.

## 4. 점검 워크플로로 확인하기 (Windows PC 그대로 됨)

Docker를 내 PC에 설치하지 않아도 됩니다. GitHub가 서버와 같은 조건으로 내 앱을 빌드하고 띄워 봅니다.

### 4.1 넣는 법

1. 이 페이지에서 `docker-check.yml` 을 내려받습니다.
2. 리포에 `.github/workflows/` 폴더를 만들고 그 안에 넣습니다. **파일 내용은 고치지 않습니다.**
3. 커밋하고 푸시합니다. 이후 푸시할 때마다 자동으로 돕니다.

### 4.2 결과 보는 법

1. GitHub 리포의 **Actions** 탭을 엽니다.
2. 맨 위 실행 기록을 누릅니다. 초록 체크면 통과, 빨간 X면 실패입니다.
3. 실패하면 빨간 단계를 열어 메시지를 봅니다. 맨 아래 "실패하면 앱 로그"에 내 앱의 오류가 나옵니다.

| 단계 | 하는 일 | 실패하면 |
|---|---|---|
| 0 | Dockerfile 문법 점검 (참고용) | 실패로 치지 않습니다. 경고는 R-02·R-15 확인에 씁니다 |
| 1 | 빌드 | Dockerfile·의존성 파일을 고칩니다 (R-01·R-02·R-10) |
| 2 | 서버 환경 준비 | — |
| 3 | 서버 조건으로 앱 실행 | R-05·R-06 |
| 4 | 30초 안에 첫 화면 응답 | R-03 (`0.0.0.0:8080`), 시작 오류 |
| 5 | 첫 화면 링크 점검. `FAIL` 이 붙은 주소는 앱 밖을 가리킵니다 | R-04 (따옴표 없는 속성, 호스트가 들어간 주소) |
| 6 | 앱을 재시작한 뒤 응답 확인, `/data` 파일 확인 | R-06 (데이터가 `/data` 에 있어야 재시작 후에도 남습니다) |
| 7 | 이미지 크기 표시 | R-16 |

### 4.3 제출할 커밋

제출 폼에는 **Actions가 초록인 커밋의 SHA**를 적습니다. 커밋 목록에서 초록 체크 옆의 복사 버튼을 누르면 40자 SHA가 복사됩니다.

### 4.4 다른 방법 (선택)

- **GitHub Codespaces**: 리포 화면의 `Code` → `Codespaces` 로 브라우저 안의 리눅스를 엽니다. 거기서 `docker build .` 를 직접 해 볼 수 있습니다. 개인 계정은 월 사용량 안에서 무료입니다.
- **내 PC의 Docker Desktop**: WSL2와 관리자 권한이 필요합니다. 집 PC라면 써도 됩니다. 판정은 점검 워크플로 결과로 합니다.

## 5. Windows에서 자주 생기는 문제

| 문제 | 증상 | 해결 |
|---|---|---|
| 줄바꿈(CRLF) | `/bin/sh^M: not found` | R-12. 셸 스크립트 entrypoint를 쓰지 않습니다 |
| `pip freeze` 결과를 그대로 씀 | `pywin32` 등 Windows 전용 패키지에서 빌드 실패 | `requirements.txt` 에는 실제로 import하는 패키지만 `==` 버전으로 적습니다 |
| 파일 이름 대소문자 | Windows에서는 되던 `Static/Style.css` 가 서버에서 404 | 파일 이름은 소문자로, 코드와 똑같이 씁니다 |
| 경로 구분자 | `"data\\voca.db"` | `DB_PATH` 환경변수를 씁니다 |
| CSV 인코딩 | 첫 열 이름이 `﻿영단어` 로 읽힘 | Python `encoding="utf-8-sig"`, Node는 BOM 제거 |
| `localhost` 로 들음 | 내 PC에서는 되는데 4단계에서 응답 없음 | R-03 |
| 파일 업로드 크기 | 큰 CSV 업로드가 거절됨 | 서버는 20MB까지 받습니다. 제공 CSV는 그보다 훨씬 작습니다 |
