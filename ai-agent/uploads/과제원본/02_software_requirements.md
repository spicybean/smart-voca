# 소프트웨어 요건 — 단어장 웹 앱

> v1.1 (2026-11-24). 요구사항 ID는 내 요구사항 명세서·README·커밋 메시지에 그대로 쓰세요.

## 0. 수업 예시와 달라진 점

| 수업 예시 | 기말 과제 |
|---|---|
| PyQt 윈도우 프로그램 또는 안드로이드 앱 | **웹 앱** (학교 서버에서 실행) |
| 암기·시험 이력을 **파일**로 저장 | **DB**로 이력 관리 |
| 단어 목록 불러오기·저장 | 단어 등록 (직접 입력 + CSV 가져오기) |
| 보고서 작성 | **학습 진척 통계** 화면 |
| — | 도전 기능: 로그인, 다른 계정 이력 보기, 설정 |

## 1. 수준

- **기본**: 반드시 만들 기능입니다. 기본 요건을 모두 채우면 만점입니다.
- **도전**: 더 해 보는 기능입니다. 가산점으로 반영합니다.

## 2. 기능 요구사항 (VOCA-FR)

확인 방법은 세 가지입니다.

- **시연**: 서버에 올라간 앱을 직접 조작해 봅니다.
- **코드**: 리포의 코드를 봅니다.
- **DB**: 테이블과 데이터를 봅니다.

### 2.1 단어 등록 — 기본

| ID | 요구사항 | 확인 |
|---|---|---|
| VOCA-FR-001 | 영단어와 뜻을 직접 입력해 등록한다 | 시연 |
| VOCA-FR-002 | 등록된 단어를 목록으로 보고, 수정·삭제한다 | 시연 |
| VOCA-FR-003 | 제공 CSV(`영단어,뜻`, 2,000개)를 가져와 일괄 등록한다. 중복 단어를 어떻게 처리할지는 직접 정하고 문서에 적는다 | 시연·코드 |
| VOCA-FR-004 | 단어를 검색한다 (영단어 또는 뜻) | 시연 |

> 제공 CSV는 UTF-8 BOM 파일입니다. Python은 `encoding="utf-8-sig"` 로 여세요. Node는 BOM을 지우고 읽으세요.

### 2.2 암기 — 기본

| ID | 요구사항 | 확인 |
|---|---|---|
| VOCA-FR-011 | 하루 학습량(단어 수)에 따라 1일차, 2일차 … 진도를 만든다 | 시연·코드 |
| VOCA-FR-012 | 그날의 단어를 한 장씩 보며 암기한다 (영단어 → 뜻 보기) | 시연 |
| VOCA-FR-013 | 전날 외운 단어 일부와 자주 틀린 단어를 그날 암기에 섞는다 | 코드·DB |
| VOCA-FR-014 | 암기 이력(누가·언제·어느 단어·몇 일차)을 DB에 남긴다 | DB |

### 2.3 시험 — 기본

| ID | 요구사항 | 확인 |
|---|---|---|
| VOCA-FR-021 | 문제 수를 정하면 그 수만큼 출제한다 | 시연 |
| VOCA-FR-022 | 무작위로 출제하되, 시험 본 적 없는 단어·오래된 단어·자주 틀린 단어가 더 많이 나오게 한다 | 코드 |
| VOCA-FR-023 | 출제 방향을 고른다: 영→한, 한→영, 섞기 | 시연 |
| VOCA-FR-024 | 출제 형식을 **2가지 이상** 지원한다 (단답형, 4지선다, OX 중에서) | 시연 |
| VOCA-FR-025 | 채점 결과(점수, 틀린 문항과 정답)를 보여준다 | 시연 |
| VOCA-FR-026 | 시험 이력을 문항 단위로 DB에 남긴다 (단어, 형식, 방향, 정오, 시각) | DB |

### 2.4 학습 진척 통계 — 기본

| ID | 요구사항 | 확인 |
|---|---|---|
| VOCA-FR-031 | 진도 현황: 현재 일차, 암기한 단어 수 / 전체 | 시연 |
| VOCA-FR-032 | 시험 성적 추이: 회차별·날짜별 정답률 | 시연 |
| VOCA-FR-033 | 자주 틀리는 단어 목록 (상위 N개) | 시연 |
| VOCA-FR-034 | 통계는 DB 이력으로 계산한다 (화면에 값을 직접 써 넣지 않는다) | 코드 |

### 2.5 로그인 — 도전

| ID | 요구사항 | 확인 |
|---|---|---|
| VOCA-FR-041 | 회원 가입, 로그인, 로그아웃 | 시연 |
| VOCA-FR-042 | 비밀번호는 해시로 저장한다 (평문 금지) | 코드·DB |

### 2.6 다른 계정 이력 보기 — 도전 (VOCA-FR-041이 필요)

| ID | 요구사항 | 확인 |
|---|---|---|
| VOCA-FR-051 | 다른 사용자의 학습 진척 통계를 본다 (예: 친구 목록, 순위표) | 시연 |
| VOCA-FR-052 | 공개 여부는 본인이 정한다. 비공개 사용자의 이력은 보이지 않는다 | 시연 |
| VOCA-FR-053 | 다른 사람의 이력은 보기만 할 수 있다. 고치거나 지울 수 없다 | 시연·코드 |

### 2.7 설정 — 도전

| ID | 요구사항 | 확인 |
|---|---|---|
| VOCA-FR-061 | 설정 화면에서 하루 학습량, 복습 비율, 시험 기본값(문제 수·방향·형식)을 바꾼다 | 시연 |
| VOCA-FR-062 | 설정은 DB에 저장되고 다시 접속해도 유지된다 (로그인을 만들었으면 계정별로) | 시연·DB |

> 하루 학습량은 기본 기능에도 필요합니다(VOCA-FR-011). 기본 수준에서는 고정값이나 간단한 입력으로 충분합니다. 설정 화면에서 저장하고 관리하는 것은 도전입니다.

## 4. 제출 요건 (VOCA-SUB)

### 4.1 리포와 제출

| ID | 요건 |
|---|---|
| VOCA-SUB-001 | GitHub 리포 하나에 앱 전체를 둔다. 리포는 **공개(Public)**로 한다 |
| VOCA-SUB-002 | `README.md` 에 앱 소개, 실행 방법, 구현한 요구사항 ID 목록, 고른 DB를 적는다 |
| VOCA-SUB-003 | 이 페이지의 제출 폼으로 낸다. 리포 URL, 제출 커밋(40자 SHA), 앱 이름, 한 줄 설명, 계정 자가 신고를 적는다. 마감 시점에 폼에 적힌 값이 제출본이다 |

### 4.2 개발 방법론 산출물 (`docs/`)

개발 방법론 문서에 따라 `docs/` 에 둡니다. 문서 이름은 방법론의 네이밍 규칙(`분류_yymmdd_제목 vX.X.md`)을 따릅니다.

| ID | 산출물 | 수준 |
|---|---|---|
| VOCA-SUB-011 | 개발 방법론 문서 (수업 배포본 사본) | 기본 |
| VOCA-SUB-012 | 프로젝트 기획서 | 기본 |
| VOCA-SUB-013 | 요구사항 명세서. 이 문서의 VOCA-FR ID를 쓰고, 구현했는지 표시한다 | 기본 |
| VOCA-SUB-014 | 시스템 아키텍처 설계서 | 기본 |
| VOCA-SUB-015 | 데이터 설계서 (테이블 정의) | 기본 |
| VOCA-SUB-016 | UI/UX 설계서, 테스트 정의서 등 2차 산출물 | 도전 |

### 4.4 서버 배포

자세한 규칙과 확인 방법은 「Dockerfile 구성」에 있습니다. 앱 주소는 `/2026/voca-<학번>/` 입니다.

| ID | 요건 |
|---|---|
| VOCA-SUB-031 | 리포 루트에 `Dockerfile` 이 있고, `docker build .` 한 번으로 이미지가 만들어진다. Dockerfile 필수 규칙 R-01~R-10을 지킨다 |
| VOCA-SUB-032 | 컨테이너는 `0.0.0.0:8080` 에서 응답한다 |
| VOCA-SUB-033 | 앱은 `/` 를 기준으로 만든다. 서버가 `/2026/voca-<학번>/` 아래로 옮겨 준다. 주소는 `/` 로 시작하는 경로나 상대 경로로 쓴다. 호스트를 쓰지 않고, HTML 속성은 따옴표로 감싼다. JS 주소는 `fetch("/api/…")` 처럼 호출하는 자리에 문자열로 쓴다 |
| VOCA-SUB-034 | UID 10001, 리눅스 권한 없이 실행해도 동작한다 |
| VOCA-SUB-035 | DB는 **SQLite**(`DB_PATH`)를 쓴다. PostgreSQL 17(`DB_HOST`·`DB_PORT`·`DB_NAME`·`DB_USER`·`DB_PASS`)은 11-30까지 사전 협의한 경우만 쓴다. 실행 중 파일 쓰기는 `/data`·`/tmp` 에만 한다 |
| VOCA-SUB-036 | 실행 중 인터넷이 필요 없다. 비밀값(세션 키 등)은 환경변수로 받는다 |
| VOCA-SUB-037 | 점검 워크플로(`.github/workflows/docker-check.yml`)를 고치지 않고 넣는다. 제출 커밋에서 통과(초록)한다 |
