**설명**: 방법론 §2.4 형상/배포관리 정의서(Deployment Spec). Git 버전 관리 규칙, 빌드와 배포 절차, 데이터 위치, 배포 검증 체크리스트를 정리한다. 방법론의 운영/배포 정의서 내용(실행 환경, 장애 복구)도 이 문서에 합쳐 다룬다.

## 1. 목적과 범위

- 소스와 문서를 어떻게 버전 관리하는지 정한다.
- 실행 파일(`SmartVoca.exe`)을 어떻게 만들고 검증하고 배포하는지 정한다.
- 범위 밖: 서버 운영, Docker/K8s, CI/CD 파이프라인은 해당하지 않는다 (데스크톱 앱, ADR-02 오프라인 동작).

## 2. 형상 관리

### 2.1 저장소

| 항목 | 값 |
|---|---|
| 원격 | `origin` = `https://github.com/spicybean/smart-voca.git` |
| 기본 브랜치 | `main` |
| 현재 사용 브랜치 | `main`만 사용 |
| 큰 파일 | `data/*.db`, `dist/`, `build/`는 Git에 올리지 않는다 (`.gitignore`) |

### 2.2 커밋 규칙

- 형식: Conventional Commits. `feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:` (CLAUDE.md).
- 이슈 번호가 있으면 끝에 `(#번호)`를 붙인다. 예: `feat: ... (#1)`.
- 커밋은 한 가지 일만 담는다. 이슈별로 나눈다.
- AI 협업 커밋에는 `Co-Authored-By` 줄을 붙인다.
- 커밋과 push는 사용자 승인 후에 한다 (CLAUDE.md).

### 2.3 브랜치 전략

- 1인 개발이므로 현재는 `main` 단일 브랜치로 운영한다.
- 위험한 변경(예: 설계 대폭 변경, 배포 설정 변경)은 브랜치를 따로 만든 뒤 `main`에 합친다. 이 방식은 필요할 때만 쓴다.

### 2.4 문서 버전 관리

- 문서는 `분류_yymmdd_제목 vX.X.md`로 쓴다. 승인된 산출물만 `docs/`에 둔다.
- 버전을 올릴 때는 이전 버전을 `docs/old/`로 옮긴다 (`git mv`), 새 버전을 복사해 수정한다 (CLAUDE.md 버전 업 절차).
- 참조 버전이 바뀌면 참조하는 문서도 같은 흐름으로 맞춘다.

## 3. 빌드

### 3.1 빌드 명령 (Windows)

CLAUDE.md의 명령이 정본이다.

```
pyinstaller --onefile --windowed --add-data "data/words_common.csv;data" --add-data "data/words_business.csv;data" --name "SmartVoca" src/main.py
```

- 산출물: `dist/SmartVoca.exe` (2026-11-18 빌드, 약 42MB).
- `--add-data`는 CSV만 넣는다. `data/` 전체를 넣으면 개발용 DB가 exe에 묶인다 (ADR-03).
- `SmartVoca.spec` 파일이 로컬에 있으나 `.gitignore`의 `*.spec`에 걸려 Git에 없다. 빌드 기준은 위 명령이다.

### 3.2 빌드 전 조건

1. venv에서 `python -m pip install -r requirements.txt`로 의존성을 맞춘다.
2. `venv\Scripts\python.exe -m pytest tests -q` 전체 통과 (기준선 211건).
3. `data/words_common.csv`, `data/words_business.csv`가 있다.

### 3.3 Mac 빌드

- 1차 범위 밖이다 (ADR-04). CLAUDE.md의 Mac 명령은 참고용이며, 검증하지 않았다.

## 4. 배포

### 4.1 배포 방식

- 학생에게 `SmartVoca.exe` 한 개를 전달한다. Python 설치는 필요 없다.
- 전달 경로는 정하지 않았다 (확인 필요). 개인 전달, 공유 폴더 등 중 선택이 필요하다.

### 4.2 버전 표시

- 현재 exe에는 버전 번호가 없다. 릴리스마다 Git 태그(예: `v1.0.0`)를 붙이는 것을 제안한다 (확인 필요).

### 4.3 배포 검증 체크리스트

배포 전에 모두 확인한다. 한 항목이라도 실패하면 배포하지 않는다.

- [ ] 자동 테스트 211건 이상 통과
- [ ] 빌드 명령으로 `dist/SmartVoca.exe` 생성
- [ ] 깨끗한 Windows 환경에서 exe 실행 (Python 미설치 상태)
- [ ] 첫 실행 시 설정 화면이 먼저 열리고, 저장 후 홈으로 이동 (FR-2.1)
- [ ] DB 파일 `smart_voca.db`가 `%APPDATA%\SmartVoca\` 아래 생성됨
- [ ] 퀴즈 한 세션 완료 후 결과 화면 표시
- [ ] 퀴즈 도중 종료 후 재실행 시 이어 풀기 가능 (FR-3.6)
- [ ] 수동 백업 생성 후 `%APPDATA%\SmartVoca\backups\`에 파일 생성
- [ ] 백업 복구 후 데이터가 백업 시점과 같음, 복구 전 임시 백업 생성 (FR-1.8)
- [ ] 로그 파일이 `%APPDATA%\SmartVoca\logs\` 아래 생성됨 (ADR-05)

## 5. 실행 환경과 데이터 위치

| 구분 | DB | 백업 | 로그 | 근거 |
|---|---|---|---|---|
| 배포 (exe) | `%APPDATA%\SmartVoca\smart_voca.db` | `%APPDATA%\SmartVoca\backups\` | `%APPDATA%\SmartVoca\logs\` | ADR-03, `src/config.py` |
| 개발 | 프로젝트 `data/smart_voca.db` | 프로젝트 `backups/` | 프로젝트 `logs/` | ADR-03, `src/config.py` |

- 환경 변수: 현재 필수 변수는 없다 (`.env.example`). 비밀값이 생기면 `.env`에만 둔다.

## 6. 장애 복구 (운영 절차)

| 장애 | 대응 |
|---|---|
| DB 손상 (강제 종료 등) | 백업에서 복구. 복구 실패 시 재초기화 (데이터 설계서 5.2, P-15) |
| CSV 손상 | 오류 메시지 표시, DB 파일을 만들지 않음 (P-01) |
| 배포 exe 실행 불가 | 직전 exe로 되돌림. 직전 exe를 보관하는 규칙이 필요 (확인 필요) |
| 학습 기록 실수로 삭제 | 자동 백업 파일에서 복구 |

## 7. 생략 판단

- **운영/배포 정의서**: 서버, 컨테이너, 모니터링 대상이 없어 독립 문서로 쓰지 않는다. 필요한 내용(실행 환경, 장애 복구)은 이 문서 5절과 6절에 합쳤다.
- 사유는 작업 일지 (`일지_261125_산출물 작성.md`)에 기록한다.

## 8. 확인 필요

1. 배포 전달 경로 (개인 전달, 공유 폴더 등).
2. 릴리스 버전 번호 체계와 Git 태그 사용 여부.
3. 직전 exe 보관 규칙.
4. `SmartVoca.spec`을 Git에 올릴지 여부 (현재 `.gitignore`로 제외).
