## 4. 기능 대조

### 4.1 단어 등록 (VOCA-FR-001~004)

| 요구 | 현재 | 판정 |
|---|---|---|
| 영단어와 뜻 직접 입력 | FR-1.3 단어 추가 | 충족 |
| 목록 보기, 수정, 삭제 | FR-1.2, FR-1.4, FR-1.7 | 충족 |

### 4.2 암기 (VOCA-FR-011~014)

| 요구 | 현재 | 판정 |
|---|---|---|

## 8. 결정이 필요한 사항

1. **플랫폼 방향** (가장 중요)
   - (A) 웹 앱으로 전환. 도메인·서비스 계층(순수 규칙, SQLAlchemy)은 재사용하고 화면을 웹으로 다시 만든다. 과제 요건을 충족한다. 1차 마감까지 5일이므로 범위 조정이 필요하다.
   - (B) 데스크톱 유지. 과제 요건을 충족하지 못한다. 교수와 협의가 필요하다.
   - (C) 웹 버전을 별도로 추가하고 데스크톱은 유지한다. 두 화면을 함께 관리하는 부담이 크다.
2. **제공 CSV 2,000개** 파일 확보. 현재 프로젝트 CSV는 1,500개다. 과제 파일을 받아야 적재 규칙을 맞출 수 있다.
3. **개인정보 이력 정리**: 공개 전 실명·학번을 이력에서도 지울지, 현재 파일만 고칠지.
4. **요구 범위**: 필수 기능 전체(암기 모드, 형식 추가, 통계 추가)를 이번 과제 범위로 볼지, 도전 기능은 제외할지.
5. **서버 경로**: 학번이 필요하다. 학번은 문서에 쓰지 않고 배포 설정에만 넣는 방식으로 할지 정해야 한다.
