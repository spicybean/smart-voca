## 이슈 1. [Bug] 단어 삭제 시 암기·시험 기록이 남음 (외래키 cascade 미설정)

## 문제
단어를 삭제해도 `study_log`, `exam_item` 기록이 남는다. SQLite 외래키 cascade가 켜져 있지 않다(`PRAGMA foreign_keys` 미설정). 재현: 회차 생성 후 단어 삭제 → 문항 5개 그대로 남음.

## 영향 범위
- `app/__init__.py`: DB 연결 시 외래키 pragma 설정 필요
- `app/word_service.py`: `delete_word` (pragma를 쓰지 않을 경우 기록을 직접 삭제)
- 테스트: 단어 삭제 후 기록 수 확인 테스트 추가

## 기대 결과
단어를 삭제하면 해당 단어의 `study_log`, `exam_item`도 함께 삭제된다 (요구사항 명세서 v2.0 VOCA-FR-003, 데이터 설계서 5장).

---

## 이슈 2. [Bug] 시험 진행 중 삭제된 단어의 문항 처리 없음

## 문제
시험을 보는 중에 단어를 지우면 그 문항을 건너뛰는 처리가 없다. 이슈 1 수정 후 문항이 지워지면 `session.items[position]` 인덱스가 어긋날 수 있다 (인덱스 오류 가능성은 아직 재현하지 않음).

## 영향 범위
- `app/exam_service.py`: `current_item`, `answer_item`
- `app/views.py`: `exam_question`, `exam_answer`

## 기대 결과
삭제된 단어의 문항은 건너뛰고 회차는 남은 문항으로 계속된다. 채점과 결과 집계가 어긋나지 않는다 (기능 프로세스 설계서 v1.0 P-09, 3장).

---

## 이슈 3. [Feature] 로그인과 계정별 이력 구현 (도전, VOCA-FR-041~043)

## 문제
로그인, 회원가입, 로그아웃, 비밀번호 해시 저장, 계정별 이력 분리가 없다. 기본 사용자 1번 하나만 쓴다.

## 영향 범위
- `app/models.py`: 사용자 테이블 추가, 기록의 `user_id` 연결
- `app/views.py`, 새 인증 모듈, 로그인 화면 템플릿
- 모든 서비스 조회: 현재 사용자 기준 필터

## 기대 결과
회원가입과 로그인 후 본인 이력만 보인다. 비밀번호는 해시로 저장한다 (요구사항 명세서 v2.0 4장, 도전 기능).

---

## 이슈 4. [Feature] 다른 계정 이력 보기 (도전, VOCA-FR-051~053)

## 문제
다른 계정의 학습 통계를 볼 수 없다. 공개 여부 설정도 없다.

## 영향 범위
- 이슈 3 선행 필요
- `app/stats_service.py`, 통계 화면

## 기대 결과
본인이 공개한 계정의 통계를 읽기 전용으로 본다. 로그인한 사용자만 볼 수 있다 (VOCA-FR-051~053).

## 이슈 5. [Feature] 설정 화면: 복습 비율과 시험 기본값 (도전, VOCA-FR-061~062)

## 문제
하루 학습량만 바꿀 수 있다. 복습 비율(현재 20%)과 시험 기본값(문제 수, 방향, 형식)이 고정되어 있다.

## 영향 범위
- `app/study_service.py`: `REVIEW_RATIO`를 설정값으로
- `app/exam_service.py`, `app/views.py`: 시험 설정 기본값
- `app/models.py`: `setting` 키 추가 (테이블은 기존 그대로)
- 설정 화면 템플릿

## 기대 결과
복습 비율과 시험 기본값을 바꾸고 DB에 저장한다. 바꾼 값이 다음 일차와 시험 설정 화면에 반영된다 (VOCA-FR-061~062).

## 이슈 6. [Data] 샘플 CSV 1459줄 형식 오류 (`gin하해`)

## 문제
`단어사전_샘플.csv` 1459줄의 영단어가 `gin하해`로 한글이 섞여 있다. 등록 시 형식 오류로 건너뛴다.

## 영향 범위
- `단어사전_샘플.csv` (원본)

## 기대 결과
영단어를 올바른 값으로 고친다. 원래 의도한 단어가 `gin`인지 다른 단어인지 확인이 필요하다. 원본을 고칠지는 사용자가 정한다.

## 이슈 7. [Data] 샘플 CSV 중복 단어 `peck`의 뜻 두 개

## 문제
`peck`이 두 번 나온다(1422줄: 쪼다, 1549줄: 분량). 현재 정책은 먼저 나온 뜻만 쓰고 두 번째는 건너뛴다. 두 번째 뜻이 사라진다.

## 영향 범위
- `app/word_service.py`: `import_csv` 중복 정책
- `단어사전_샘플.csv`
- 요구사항 명세서 v2.0 2.1절 (정책 문서화)

## 기대 결과
정책을 정한다. 후보: (a) 먼저 나온 뜻 유지 (현재), (b) 뜻을 `/`로 합치기. 정하면 코드와 문서를 맞춘다.

## 이슈 9. [Feature] 폼에 CSRF 보호 추가

## 문제
모든 POST 폼에 CSRF 토큰이 없다. 다른 사이트에서 학생이 모르게 단어 삭제나 시험 답을 보낼 수 있다.

## 영향 범위
- `app/__init__.py`: 보호 설정
- `app/templates/*.html`: 폼마다 토큰 필드

## 기대 결과
모든 POST 요청에 토큰이 필요하다. 토큰이 없거나 틀리면 거부된다. 서버 규칙(R-08, 비밀값 환경변수)을 지킨다.
