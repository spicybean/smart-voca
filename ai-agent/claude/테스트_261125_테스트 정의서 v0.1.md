## 1. 목적과 범위

- 요구사항 FR과 설계 규칙이 테스트로 검증되는지 확인하는 기준을 정한다.
- 자동 테스트(`tests/`)와 수동 검증(화면 점검, 배포 검증)을 나눠 기록한다.
- 범위: 도메인 규칙, 서비스(DB 포함), 화면(PyQt6 오프스크린), 실행 진입점.

## 2. 도구와 실행 방법

| 항목 | 값 |
|---|---|
| 테스트 도구 | pytest 9.2.0 |
| 실행 명령 | `venv\Scripts\python.exe -m pytest tests -q` |
| 화면 테스트 | `QT_QPA_PLATFORM=offscreen` 환경 변수를 테스트 파일 상단에서 설정 |
| DB 테스트 | `conftest.py`의 `db_engine` 픽스처가 임시 DB를 만든다. `data/`에 쓰지 않는다 |
| 주의 | 시스템 Python에서는 의존성이 없어 실행되지 않는다. venv를 쓴다 |

## 5. BDD 시나리오 (대표 항목)

시나리오는 Given/When/Then으로 쓴다. 대응 테스트를 함께 적었다.

| 요구 | 시나리오 | 대응 테스트 |
|---|---|---|
| FR-2.1 | Given 첫 실행으로 DB를 새로 만듦 / When 설정 화면에서 아무것도 바꾸지 않고 [저장] / Then 홈으로 이동 | test_first_run_window.py `test_saving_on_first_run_moves_to_home` |
| FR-3.6 | Given 퀴즈 중 현재 문항의 단어를 삭제 / When 그 문항에 답함 / Then 답은 저장되지 않고 다음 문항으로 넘어감 | test_quiz_service.py `test_answer_for_deleted_current_word_is_skipped_without_quiz_row` |
| FR-3.6 | Given 재개 전에 단어를 삭제 / When 이어 풀기 / Then 삭제된 문항은 빠진 채 남은 문항부터 진행 | test_quiz_service.py `test_resume_drops_items_for_deleted_words` |
| FR-1.6 | Given 같은 단어에 같은 문장이 있음 / When 같은 문장을 다시 추가 / Then 중복 대화상자가 뜨고 저장되지 않음 | test_example_service.py `test_duplicate_sentence_is_rejected_and_not_saved`, test_ui_word_detail.py `test_duplicate_user_example_shows_warning_and_is_not_saved` |
| FR-3.1-F | Given 같은 한글 뜻의 단어가 여러 개 / When 한 세션 구성 / Then 같은 뜻은 한 번만 출제 | test_quiz_builder.py (ADR-08) |

## 8. 결과 기록 규칙

- 실행할 때마다 날짜, 명령, `passed`/`failed` 건수를 일지에 남긴다.
- 실패가 나면 원인과 조치를 같은 일지에 적고, 원인이 요구 변경이면 요구 버전을 올린다.
- 기준선이 바뀌면 3절 표를 갱신한다.

## 9. 알려진 한계

- 화면 테스트는 오프스크린이라 실제 창의 크기와 글꼴 렌더링은 확인하지 않는다 (M-1로 보완).
- 배포 exe는 자동 테스트 대상이 아니다 (M-2~M-5로 수동 확인).
- 진도 계산은 날짜를 주입해서 테스트한다. 자정을 넘는 실제 사용 흐름은 확인하지 않았다.
