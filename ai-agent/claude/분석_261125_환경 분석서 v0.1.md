**버전**: v0.1
**설명**: 방법론 §2.2 환경 분석서(External Analysis). 비즈니스 환경, 유사 사례, 기술 환경, 외부 데이터, 제약과 위험을 정리한다. 구체 결정은 시스템 구조 설계서의 ADR이 정본이다.

## 1. 목적과 범위

- 스마트보카가 놓인 사용 환경(학생 개인 PC, 오프라인)과 기술 환경을 정리한다.
- 기술 선택의 전제가 되는 환경 조건을 한곳에 모아, 나중에 조건이 바뀌었을 때 어느 결정을 다시 봐야 하는지 알 수 있게 한다.
- 범위 밖: 내부 현황과 기존 프로세스는 현황 분석서 대상이지만, 기존 시스템이 없는 신규 개발이라 작성하지 않는다 (§8 생략 사유).

## 2. 사용 환경 (비즈니스 환경)

| 항목 | 내용 | 근거 |
|---|---|---|

| 사용 장소 | 개인 Windows PC. 인터넷 연결을 가정하지 않음 | ADR-02, ADR-04 |

| 데이터 범위 | 단어·예문·학습 기록. 개인 학습 기록은 한 기기 안에서만 관리 | 기획서, ADR-03 |
| 개발 방식 | 1인 개발 + AI 에이전트(Claude Code) 협업 | CLAUDE.md |

## 3. 유사 사례 조사

| 사례 | 확인한 내용 | 스마트보카에 준 영향 |
|---|---|---|
| vocabulary.com | 홈 화면 구성 (밝은 배경, 단순한 메뉴, 주요 행동 강조) | UI 개편 방향 (2026-11-11 UI 개편 일지) |
| 간격 반복 학습 | 복습 간격을 정답 연속 횟수로 늘리는 방식 | 간격 규칙 FR-4.0 (구체 참고 자료는 이번 문서에서 조사하지 않음, 확인 필요) |

- 학습 화면(카드, 퀴즈 피드백)의 세부 모습은 공개 자료에서 확인되지 않아 임의로 정하지 않았다 (UI 개편 일지).
- 유사 학습 앱의 기능 비교표는 작성하지 않았다. 필요하면 별도 조사로 보강한다.

## 4. 기술 환경

### 4.1 소프트웨어 스택

| 구분 | 선택 | 버전 | 근거 |
|---|---|---|---|
| 언어 | Python | 3.11 이상 요구, 개발 venv는 3.14.3 | requirements.txt, `venv/pyvenv.cfg` |
| GUI | PyQt6 | 6.12.0 | ADR-01 |
| DB | SQLite (SQLAlchemy ORM) | SQLAlchemy 2.1.8 | 데이터 설계서 |
| 테스트 | pytest | 9.2.0 | 테스트 정의서 |
| 배포 | PyInstaller (`--onefile --windowed`) | 6.22.3 | ADR-03, 형상·배포관리 정의서 |

### 4.2 개발 환경

- OS: Windows 11 Pro (개발 PC).
- 가상환경: 프로젝트 루트의 `venv/`. 설치 명령은 `python -m pip install -r requirements.txt`.
- 시스템 Python에는 의존성이 없다. 테스트와 실행은 반드시 venv로 한다 (2026-11-25 확인: 시스템 Python에서 `sqlalchemy` 없음).
- 버전 관리: Git, 원격 `origin` (GitHub). 현재 브랜치 `main`만 사용.

### 4.3 실행 환경

- 개발 모드: 프로젝트 `data/` 아래 DB를 쓴다 (ADR-03).
- 배포 모드: `%APPDATA%\SmartVoca\` 아래 DB, 백업, 로그를 쓴다 (`src/config.py`).
- 오프라인 동작. 외부 API 호출 없음 (ADR-02).

## 5. 외부 데이터

| 데이터 | 규모 | 출처와 상태 |
|---|---|---|
| 기본 단어 (일상) | 1,000개 (`data/words_common.csv`) | 프로젝트 제작 CSV, 커밋 대상 |
| 기본 단어 (비즈니스) | 500개 (`data/words_business.csv`) | 프로젝트 제작 CSV, 커밋 대상 |
| 기본 예문 | CSV의 `example_1~3`, 단어당 최대 3개 | CSV에 포함 (ADR-02) |
| 외부 사전 API | 사용하지 않음 | 검토 결과는 ADR-02 참조 |

- 같은 한글 뜻을 가진 단어가 160건 있다. 문항 선정 규칙으로 처리했다 (ADR-08).
- 개발용 DB `data/smart_voca.db`는 Git에 올리지 않는다 (`.gitignore`).

## 6. 제약 조건

1. **인터넷 없이 동작해야 한다.** API 키 없이 실행된다 (ADR-02).
2. **Windows 우선.** macOS 빌드는 1차 범위 밖이다 (ADR-04). 재검토 조건: Mac 사용자 배포 요청.
3. **설치 없는 배포.** exe 한 개로 배포한다 (ADR-03). 최신 산출물 `dist/SmartVoca.exe`는 약 42MB다 (2026-11-18 빌드 기준).
4. **보안.** 외부 전송 없음, 비밀값은 `.env`에만 둔다 (요구사항 3.4, `.env.example`).

## 7. 위험과 대응

| 위험 | 영향 | 대응 | 관련 결정 |
|---|---|---|---|
| PyQt6의 GPL 조건 | 배포 시 소스 공개 의무 검토 필요 | 배포 계획 확정 전 재검토. 필요하면 PySide6로 전환 가능하도록 Qt 공통 API 위주로 작성 | ADR-01 |
| 최신 Python(3.14)에서 exe 동작 | 빌드 산출물이 실행되지 않을 수 있음 | 깨끗한 PC에서 exe 실행 검증 (형상·배포관리 정의서 체크리스트) | 형상·배포관리 정의서 |
| 뜻 중복 단어 160건 | 한→영 문항 정답 중복 | 세션 단위 중복 방지 규칙 적용 | ADR-08 |
| 학생이 추가하는 단어가 많아짐 | 직접 입력 부담, 예문 품질 문제 | 재검토 조건 충족 시 외부 연동 인터페이스 재설계 | ADR-02 |
| DB 손상 | 학습 기록 손실 | 자동 백업, 복구 전 임시 백업 | FR-1.8 |

## 8. 생략 판단

- **현황 분석서**: 기존 시스템과 기존 프로세스가 없는 신규 개발이므로 작성하지 않는다.
- 사유는 작업 일지 (`일지_261125_산출물 작성.md`)에 기록한다.

## 9. 확인 필요

1. 실제 학생 PC 환경(해상도, 권한, 백신 차단 여부)에서 exe를 실행한 기록은 없다.
2. Mac 사용자 요구가 있는지 확인이 필요하다.
3. 간격 반복 방식의 외부 참고 자료는 조사하지 않았다.
