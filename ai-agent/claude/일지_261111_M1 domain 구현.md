## 2026-11-11 — M2 설정·DB 모델 구현

**요청**: M2 진행
**처리**:
- `src/config.py`: 실행 모드 판정, DB·백업·로그 경로, `.env` 로드 (개발 모드에서만)
- `src/utils.py`: 영단어 정규화, 로컬 오늘 날짜, 리소스 경로 (PyInstaller `_MEIPASS` 대응)
- `src/logger.py`: `smartvoca` 로거, 1MB 로테이션 3개, 개발 모드 콘솔 출력
- `src/database.py`: 엔진 생성 (연결마다 `PRAGMA foreign_keys = ON`), `init_engine`, `session_scope`
- `src/models.py`: 테이블 7개 (데이터 설계서 v1.2 스키마, CHECK·UNIQUE·인덱스 포함)
- `requirements.txt`, `venv/` 생성 (pytest 등 설치)
- 테스트: `tests/test_models.py`, `test_database.py`, `test_config_utils.py`, `test_logger.py`, `conftest.py`에 `db_engine` 픽스처 추가

**설계서와 다르게 구현한 부분**:
1. `get_data_dir()`은 DB 폴더를 돌려준다. 개발 모드에서는 `data/`이고 백업·로그는 프로젝트 루트의 `backups/`, `logs/`다. 설계서 4.8절 표와 맞추기 위해 함수를 나눴다.
2. `create_db_engine`은 `':memory:'`를 받으면 `StaticPool`로 인메모리 DB를 만든다. 설계서의 인메모리 픽스처 요구를 따랐다.
3. `.env`는 개발 모드에서만 읽는다. 배포 exe에는 키를 넣지 않는다는 설계서 12장 방침을 따랐다.
4. 엔진은 `check_same_thread=False`로 만든다. QThread 워커에서도 같은 엔진을 쓰기 위해서다.

**검증 현황**: `venv\Scripts\python.exe -m pytest tests/ -q` → **76 passed** (M1 48 + M2 28). 테스트 실행 후 프로젝트 안에 `logs/`, `backups/`, `smart_voca.db`가 생기지 않았다.

**다음 단계**: M3 (`services/db_init.py`, `ai-agent/scripts/init_db.py`, CSV 1,500행 로드 테스트)
