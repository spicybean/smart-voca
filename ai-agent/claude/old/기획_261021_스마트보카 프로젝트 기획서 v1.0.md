## 3. 시스템 범위 및 기능 (SS)

### 3.1 포함 기능 (In Scope)

#### v1.0 핵심 기능

| 기능명 | 설명 | 우선순위 |
|--------|------|----------|
| **단어 등록/관리** | 학생이 학습할 단어를 등록, 조회, 삭제 | 필수 |
| **사전 API 연동** | 단어 입력 시 공식 사전에서 예문 조회 | 필수 |
| **분야별 학습** | 분야 선택 (일상/비즈니스) 및 필터링 | 필수 |
| **일일 학습 설정** | 학습량(개수)과 분야 커스텀 설정 | 필수 |
| **4지선다형 퀴즈** | 한→영, 영→한 양방향 4지선다형 문제 | 필수 |
| **보너스 문제** | 기본 퀴즈 후 약한 단어 추가 출제 | 필수 |
| **학습 진도 추적** | 개인의 단어별 습득 상태 시각화 | 필수 |

#### 기능 상세

**3.1.1 단어 등록/관리**
- **초기 데이터 로드**: 1,500개 사전 등록 단어 (CSV 기반, 앱 첫 실행 시 자동 로드)
  - 일상 영단어: 1,000개
  - 비즈니스/취업 단어: 500개
- 학생이 추가로 새 단어 등록 가능
- 단어 목록 조회 (테이블 형식)
- 단어 삭제
- 단어 검색 (키워드 기반)

**3.1.2 사전 API 연동**
- 단어 입력 → 사전 API 호출 (예: WordsAPI, Cambridge Dictionary)
- 반환된 예문 3~5개 자동 표시
- 학생이 직접 예문 추가 가능 (수동 입력)

**3.1.3 간격 반복 퀴즈**

**기본 퀴즈 구성** (설정된 개수, 예: 10개/일):
- 4지선다형 문제만 사용 (자동 채점 가능)
- **양방향 문제**:
  - 한글→영어: "사과는?" → ① apple ② banana ③ orange ④ grape
  - 영어→한글: "apple은?" → ① 사과 ② 바나나 ③ 오렌지 ④ 포도
  - 비율: 50% 한→영, 50% 영→한

**4지선다형 보기 선정 알고리즘** (혼합 방식):
- **v1.0 (초기 - 100개 퀴즈까지)**:
  1. 정답 단어의 카테고리와 난이도 확인
  2. 같은 카테고리에서 난이도 ±1 범위의 단어 3개 무작위 선택
  3. 정답 1개 + 오답 3개를 섞어서 출제
  
- **v1.1 이후 (100개 퀴즈 초과 시)**:
  1. 학생이 자주 틀린 단어 확인 (correct_rate < 70%)
  2. 자주 틀린 단어가 2개 이상이면:
     - 오답 2개 = 자주 틀린 단어
     - 오답 1개 = 같은 카테고리의 임의 단어
  3. 자주 틀린 단어가 2개 미만이면:
     - 방식 v1.0 계속 사용 (카테고리+난이도)

**보너스 문제** (기본 퀴즈 완료 후):
- 설정된 문제 N개 완료 후, 자동으로 추가 출제
- 대상: 자주 틀린 단어 + 외운지 오래된 단어
- 개수: 3~5개 (정답률에 따라 동적 결정)
- 선택사항: [보너스 도전하기] / [건너뛰기]
- 보너스 정답 점수는 기록되지만 선택사항

**학습 상태 분류**:
- 미학습: 처음 배우는 단어 (correct_count = 0)
- 학습 중: 1회 이상 정답, 정답률 ≥ 70% (correct_count ≥ 1)
- 복습 필요: 정답률 < 70% (correct_count ≥ 1)
- 숙달: 정답률 ≥ 80% 이고, 마지막 복습이 30일 이상 전

**간격 반복 알고리즘** (Spaced Repetition):
- **복습 일정 결정**: 학습 상태와 정답 여부로 결정
  
  | 현재 상태 | 정답 시 | 오답 시 |
  |----------|--------|--------|
  | 미학습 | 1일 후 | 즉시 (다음 세션) |
  | 학습중 (1회) | 3일 후 | 1일 후 |
  | 학습중 (2~4회) | 7일 후 | 2일 후 |
  | 학습중 (5회 이상) | 30일 후 | 3일 후 |
  | 복습필요 | 3일 후 | 1일 후 |
  | 숙달 | - | 3일 후 |

- **오답 처리**: 오답 시 학습 상태 초기화 또는 낮춤
  - 현재 correct_rate 유지하되, correct_count 초기화 아님
  - wrong_count 증가
  - 복습 일정 단축

**3.1.4 일일 학습 설정**
- **학습 분야 선택**: 일상 / 비즈니스 / 커스텀 분야
- **일일 학습량 설정**: 5개 / 10개 / 15개 / 커스텀

**오늘의 퀴즈 구성** (일일 학습량이 10개 예시):
- 구성 비율:
  - 새 단어 또는 약한 단어 (정답률 < 70%): 50~70% (5~7개)
  - 전날 복습 대상 단어: 20~30% (2~3개)
  - 자주 틀린 단어 (정답률 < 60%, 7일 이상 미복습): 10~20% (1개)
  - 합계: 설정값(10개)

**"전날 복습 대상" 단어 정의**:
- 조건: 복습 예정일이 오늘인 단어
  - 마지막 복습이 1일 전: 다음 복습일 = 오늘
  - 마지막 복습이 3일 전: 다음 복습일 = 오늘
  - 즉, `last_reviewed_date + next_review_interval = 오늘`
- 선정 방식: 복습 예정 단어를 먼저 선정, 부족시 학습중 단어로 채우기

**보너스 문제** (기본 퀴즈 완료 후):
- **트리거**: 기본 퀴즈 N개 완료 → 자동으로 보너스 문제 제시
- **보너스 문제 선정 기준** (AND 조건):
  1. 정답률 < 60% AND
  2. 마지막 복습이 7일 이상 전
  3. 최대 5개 범위 (조건 만족하는 단어가 5개 이상이면 상위 5개)

**선정 우선순위** (조건 만족 단어 정렬):
  1차: 정답률 낮은 순
  2차: 마지막 복습이 오래된 순
  
**예시**:
  | 단어 | 정답률 | 마지막복습 | 선정 |
  |------|--------|----------|------|
  | deadline | 40% | 15일전 | ✅ (둘다만족) |
  | negotiate | 55% | 10일전 | ✅ (둘다만족) |
  | portfolio | 65% | 20일전 | ❌ (정답률 60% 이상) |
  | resume | 50% | 3일전 | ❌ (복습 7일 미만) |

- **보너스 선택사항**: [보너스 도전하기] / [건너뛰기]
- **보너스 점수 기록**: 보너스 정답은 기록하지만 진도에 큰 영향 없음

**3.1.5 학습 진도 추적**
- 대시보드:
  - 전체 단어 수
  - 학습 완료 단어 수
  - 오늘 학습할 단어 수
  - 전체 진도율 (%)
- 단어별 상태 표시:
  - 습득도 (%)
  - 마지막 복습일
  - 정답/시도 횟수
- 분야별 진도율 표시

## 6. 데이터 개요

### 6.1 주요 데이터

| 엔티티 | 설명 | 속성 |
|--------|------|------|
| **Word (단어)** | 학습 대상 단어 | id, english, korean_meaning, category, level, created_date, updated_date |
| **Example (예문)** | 단어별 예문 | id, word_id, sentence, source (사전/사용자 입력) |
| **Progress (진도)** | 학습 진도 | id, word_id, status, correct_count, wrong_count, last_reviewed_date, correct_rate |
| **Settings (설정)** | 학생 학습 설정 | id, selected_category, daily_word_count, last_updated_date |
| **Quiz (퀴즈 기록)** | 퀴즈 풀이 기록 | id, word_id, quiz_type (한→영/영→한), is_correct, is_bonus, created_date |

### 6.2 데이터 저장소
- **SQLite 파일**: `smart_voca.db` (프로젝트 루트 또는 지정 디렉토리)
- **CSV 파일** (초기 데이터):
  - `data/words_common.csv` (일상 단어 1,000개)
  - `data/words_business.csv` (비즈니스/취업 단어 500개)
  - 형식: `english, korean, category, level`

### 6.3 초기 데이터 로드 절차
1. 앱 첫 실행 시 `init_db.py` 스크립트 자동 실행
2. CSV 파일에서 단어 데이터 읽기
3. SQLite DB의 Word 테이블에 1,500개 단어 일괄 로드
4. Progress 테이블은 "미학습" 상태로 초기화
5. 이후 학생이 직접 등록한 단어는 추가로 로드됨

9. **Python 설치 불필요**: 최종 사용자는 Python 설치 불필요 (exe/app에 포함)

### 10.2 에러 처리 전략

**예상되는 실패 시나리오와 대응**:

| 시나리오 | 원인 | 대응 방법 |
|---------|------|----------|
| **API 호출 실패** | 네트워크 오류, API 서버 다운 | 캐시된 예문 사용, 사용자 입력 예문 허용 |
| **CSV 파일 손상** | 파일 오류, 인코딩 문제 | 오류 메시지 표시, 초기화 다시 시도 |
| **DB 손상** | 앱 강제 종료 등 | DB 복구 시도, 실패 시 재초기화 |
| **API 일일 한도 초과** | 프리 플랜 제한 | 캐시 사용, 다음날까지 대기 안내 |

**구현 방식**:
```python
# API 호출
try:
    response = call_words_api(word)
except APIError:
    # 1차: 캐시에서 조회
    cached = get_cached_examples(word)
    if cached:
        return cached
    
    # 2차: 사용자가 입력한 예문 사용
    user_examples = get_user_examples(word)
    if user_examples:
        return user_examples
    
    # 3차: 실패 메시지
    return {"error": "예문을 불러올 수 없습니다. 나중에 다시 시도하세요."}
```
